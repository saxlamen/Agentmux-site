Setting up an agent that works all night takes about fifteen minutes: SSH into a machine you own, tmux so a dropped phone connection detaches instead of stopping the agent, and Tailscale so no port faces the public internet. Answer three questions about your machine, your agent, and where you connect from, and the wizard builds the checklist.

Every step says why you're doing it, what to run, how to check that it worked, and where to look if it didn't. (Is that machine running Windows? Read this first.)

That machine runs Windows

Answer "a Windows PC" and the wizard hands you a checklist like every other answer: switch on the SSH server, stop the PC from sleeping, install your agent, and psmux gets installed by itself. This section is for the two things that stop people arriving from the other paths: what replaces tmux on a Windows host, and whether the WSL2 route they read about somewhere else is still required.

The short version: Windows 10 and 11 ship an OpenSSH Server you switch on in PowerShell, and persistence comes from psmux, a tmux-compatible program written for Windows, which Agentmux installs when the host is missing it. You do not need WSL2, a virtual machine, or a port forward. The Windows server article has the commands, what a Windows session gives you, and what is still different from a Linux box.

WSL2 is still the right pick when you want Linux userland programs rather than a Windows box. Inside it the "Linux box" path applies unchanged, so answer the wizard's first question that way. Three snags come with it, none of which a Mac has: sshd sits behind NAT inside the virtual machine, the distribution shuts down seconds after WSL's last process exits, and systemd is off by default on older installs. All three are written out with their fixes in the WSL2 section of that article.

What if your Windows PC is the machine you work at?

The Windows discussed here is always the machine you connect to. If your Windows PC is the computer you work at, and the agent runs somewhere else (a Mac mini at home, a Linux box at the office, a VPS), none of the above applies. The guide works for you as written, and the machine to set up is not the one in front of you.
