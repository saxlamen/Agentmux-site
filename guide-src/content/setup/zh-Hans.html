把 agent 放到远程跑一整晚，大约 15 分钟：用 SSH 连进你自己那台机器，用 tmux 让手机掉线时只是 detach、不会停止 agent，再用 Tailscale，就不用对公网开端口。回答三个问题：你的机器、要跑的 agent、你想从哪里连。清单会照你的答案生成。

每一步都会告诉你为什么要做、命令是什么、怎么确认成功了，还有没成功的话去哪里看。（那台机器是 Windows？先看这一节。）

那台机器是 Windows

选「一台 Windows 电脑」，向导会跟其他答案一样给你清单：打开 SSH 服务器、别让电脑休眠、装你的 agent，psmux 它会自己处理。这一节解决两个常见疑问：Windows 上用什么取代 tmux，还有你在别处读过的 WSL2 现在还要不要用。

先讲结论：Windows 10 和 11 都有 OpenSSH Server，用 PowerShell 打开就好。撑住 session 的是 psmux：命令照 tmux 那套设计，为 Windows 写的。那台机器没装的话，Agentmux 会帮你装。不用 WSL2、不用虚拟机，也不用转发端口。命令、Windows 的 session 能做什么、跟 Linux 主机哪里不一样，全部在这篇 Windows 主机指南。

如果你想要的是 Linux 生态而不是 Windows，就继续用 WSL2。WSL2 里面是完整的 Linux，「Linux 主机」那条路照样适用，回去把第一题改成「一台 Linux 主机」。它附带三个 Mac 没有的坑：sshd 躲在虚拟机的 NAT 后面、WSL 最后一个进程结束几秒后发行版就会关掉、旧版默认没有 systemd。三个坑的解法写在那篇 WSL2 那一节。

如果 Windows 只是你工作用的那台电脑呢？

这里讲的 Windows，指的从来是「那台被连进去的机器」。如果你的 Windows 只是你平常工作的电脑，agent 跑在别的机器上（家里的 Mac mini、公司的 Linux 主机、一台 VPS），那上面这些你一个都不会遇到，这份指南对你完全适用。你要配置的机器，不是你手上这台。
