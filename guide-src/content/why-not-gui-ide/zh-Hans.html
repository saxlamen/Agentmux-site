你已经有了 Cursor，或是 VS Code 加一个 agent 插件，用得很顺。为了同一件事去学 SSH 和 tmux，只有一种情况划算：你人不在那台电脑前面。

差别在架构，不在偏好

GUI IDE 里的 agent 是那个 GUI 程序的一部分。它活在应用的进程里，状态存在那个窗口的内存里，输出画在那块画布上。所以它需要一块屏幕、一个已登录的桌面 session、一个坐在前面的人。关掉窗口，agent 就跟着结束。这不是谁的失误：agent 本来就在那个进程里面。

CLI agent 的接口是一条字节流：读进来字符，吐出去字符，中间没有图形的东西。这种流可以被接上、拔掉、再接回去。

tmux 做得到这件事，是因为一个 80×24 的字符矩阵可以完整保存下来，再画到任何一块屏幕上：你的笔记本、你的手机、你朋友的 iPad。换一台设备不会少掉任何东西，因为那些内容本来就只是字符。

CLI agent 能在远程跑，理由只有这一个：一块像素画布没法序列化之后再接回来，一个字符矩阵可以。这话说的是能力，不是用文字界面的人更厉害。

合上笔记本之后会发生什么事？

假设你下班前丢了一个大重构给 agent，估计要跑二十分钟以上，而你现在要走了。

合上笔记本 agent 停 agent 继续跑
两小时后 打开，上下文断了，重跑 手机打开，看到它做完了

右边那一栏跟 agent 有多聪明没关系。那个 session 从头到尾就不住在你的笔记本上。它住在那台一直没关的机器上，你的笔记本只是接上去用了一阵子。合上盖子，断开的是连接，不是工作。

Cursor 现在也有云端后台 agent，合上笔记本一样继续跑。但继续跑的是 Cursor 自己远程沙盒里的那份副本，不是你机器上这一份。它跟本站另一篇讲过的网页版 agent、Codespaces 是同一类东西，左栏写的是你机器上那一个。

“那用远程桌面（VNC）不就好了？”

这是最常见的反驳，理论上完全讲得通：桌面留在那台机器上，你用 VNC 连回去，Cursor 一样开着，看起来就解决了。

实际用起来，两者传的东西完全不同。VNC 传像素，SSH 传字符。一整块屏幕更新是几百 KB 到几 MB 的图像数据，同一块画面用字符表示只有几 KB 的文字，大约差了一千倍。

这是你天天会踩到的差距。在地铁上、在电梯里、在信号只剩一格的地方，VNC 变成卡顿的幻灯片，滑一次要等三秒才画出来。同样的网络，SSH 的字符照样实时送到。

就算带宽完全够用，那个桌面 UI 本来是给鼠标和 1440p 屏幕设计的，现在被塞进六英寸的触控屏幕。点一个菜单要先放大、再对准、再点。连接再快，那个界面也不会变得好用：它从来不是为触控设计的。

坐在桌前，IDE 常常更好用

IDE 不是错的工具。坐在桌前写代码，IDE 常常更好用：跳转定义、重构、调试器，这些在手机上都做不到。IDE 适合“你在场、你主导”，CLI agent 加远程适合“它在跑、你抽查”。用得好的人两个都留着：白天在 Mac 上用 IDE，离开座位用 Agentmux 接回同一个项目的同一个 agent。

Agentmux 不是要取代你的 IDE，它取代的是坐在椅子上等。然后你把手机放进口袋，走进没有信号的楼梯间，连接断了。那个 session 接下来会怎样，要看你怎么接回去。
