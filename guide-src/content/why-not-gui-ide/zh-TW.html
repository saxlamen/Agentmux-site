你已經有 Cursor 了，或者 VS Code 加一個 agent 外掛，用得也很順。那為什麼要為了同一件事去學 SSH 和 tmux？

跟哪個比較好用無關。這是架構上的差別，而且只在你不在電腦前面的時候才現形。

差別在架構，不在偏好

GUI IDE 裡的 agent 是那個 GUI 程式的一部分。它活在應用程式的 process 裡，狀態存在那個視窗的記憶體裡，輸出畫在那塊畫布上。所以它需要一塊螢幕、一個已登入的桌面 session、一個坐在前面的人。關掉視窗，agent 跟著結束。沒有人設計失誤，它本來就長在那個 process 上。

CLI agent 的介面是一條位元組流。讀進來字元，吐出去字元，中間沒有一段需要圖形。而字元流可以被接上、拔掉、再接回去。

tmux 做得到這件事，是因為一個 80×24 的字元矩陣可以完整存下來，再畫到任何一塊螢幕上——你的筆電、你的手機、你朋友的 iPad。換裝置不會失真，因為那些內容本來就只是字元。

所以 CLI agent 能遠端只有一個理由：一塊像素畫布沒辦法被序列化後重新接上，一個字元矩陣可以。跟比較 geek 無關，跟用文字介面的人比較厲害也無關。這是能力上的差別。

同一個情境，跑兩次

假設你在下班前丟了一個大重構給 agent。估計要跑二十分鐘以上，而你現在要走了。

Cursor 開著 tmux + Claude Code
合上筆電 agent 停 agent 繼續跑
兩小時後 打開，脈絡斷了，重跑 手機打開，看到它做完了

右邊那一欄跟 agent 有多聰明沒關係。那個 session 從頭到尾就不住在你的筆電上。它住在那台沒關過的機器上，你的筆電只是接上去看過它一陣子。合上蓋子，斷掉的是連線，不是工作。

Cursor 現在也有雲端背景 agent，闔上筆電一樣繼續跑。但它續的是 Cursor 自己遠端沙箱裡的那份副本，不是你機器上這一份。那跟本站另一篇提到的網頁版 agent、Codespaces 是同一類，不是左欄的例外。

「那用遠端桌面（VNC）不就好了？」

這是最常見的反駁，理論上完全講得通。桌面留在那台機器上，用 VNC 連回去，Cursor 一樣開著，不就解決了？

實務上兩者傳的東西根本不同層級。VNC 傳像素，SSH 傳字元。一整塊螢幕更新是幾百 KB 到幾 MB 的影像資料；同一塊畫面用字元表示是幾 KB 的文字。千倍量級。

而且這是你天天會踩到的差距。在捷運上、在電梯裡、在訊號只剩一格的地方，VNC 退化成一格一格的幻燈片，滑一次要等三秒才畫出來。同樣的網路，SSH 的字元照樣即時。

就算頻寬完全不是問題，你面對的還是一個為滑鼠和 1440p 螢幕設計的桌面 UI，被塞進六吋觸控螢幕。點一個選單要先放大、再對準、再點。用觸控操作一個沒有為觸控設計過的介面，這件事本身就是折磨。

誠實地收尾

GUI IDE 不差。坐在桌前寫 code，IDE 常常更好用——跳轉定義、重構、除錯器，這些手機上都做不到。分工比想像中單純：IDE 適合「你在場、你主導」，CLI agent 加遠端適合「它在跑、你抽查」。效率高的人兩個都用。白天在 Mac 上用 IDE，出門用 Agentmux 接回同一個專案的同一個 agent。

Agentmux 不是要取代你的 IDE。它取代的是坐在椅子上等。
