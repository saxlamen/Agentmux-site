支援。Agentmux 可以直接用 SSH 連一台原生 Windows 電腦，裡面不必裝 Linux。打開 Windows 10 或 11 就有的 OpenSSH Server，把那台機器加進來，你拿到的是 PowerShell 終端機、靠 psmux 撐住的持久 session，還有你的 coding agent。

過去的標準答案是「先塞一個 WSL2」。理由只有一個：少了 tmux，手機一斷線，agent 跟著死。現在有一個為 Windows 寫的程式補上這個位置，WSL2 就從必經之路變成你可以選的路。

那台 Windows 上要準備兩樣東西

第一樣是一扇 SSH 的門。Windows 10 和 11 都把 OpenSSH Server 做成可選擇的功能，用 PowerShell 以管理者身分裝一次：

# PowerShell，以管理者身分執行
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
Start-Service sshd
Set-Service -Name sshd -StartupType Automatic

安裝過程會自動加一條名為 OpenSSH-Server-In-TCP 的入站防火牆規則。如果你的機器防火牆比較嚴，先檢查那一條。第二行現在就把服務開起來，第三行讓它重開機之後還在。這條在 Windows 上比在 Mac 上要緊，因為 Windows 會自己決定什麼時候更新重開。

第二樣是 multiplexer。Agentmux 會先問那台機器是什麼系統，Windows 的答案不一樣，所以 app 走另一條路：自己的指令改用 PowerShell 而不是 sh -c，路徑用磁碟機代號而不是斜線，multiplexer 用 psmux 而不是 tmux。這一切都是 app 自己判斷，你不用找開關。你的登入 shell 是 PowerShell 還是 cmd.exe，它也不在意。

為什麼是 psmux 不是 tmux

psmux 是另一個程式，指令列照 tmux 的設計：session、window、pane、send-keys、capture-pane 都有，還會順便裝一個 tmux.exe 的別名，手上的按法不用改。Agentmux 依序找 psmux、pmux、tmux.exe，找到哪個就用哪個，所以那台機器早就裝過就不會動它。

它不是 tmux 的 port，也不假裝是。app 會看那個程式實際回什麼，而不是看版本字串，缺的功能就乾脆不用。底下那份「哪裡不一樣」的清單就是這樣來的。

想知道為什麼非要有這個程式，這篇講得很短：連線斷掉，shell 收到 SIGHUP，沒有 multiplexer 的 agent 就跟著走了。

沒裝 psmux 會怎樣

app 會幫你裝。它先試 winget install -e --id marlocarlo.psmux，沒有就試 Scoop，再沒有就試 cargo install psmux，用機器上有的那個裝完再重連。手機這邊你什麼都不用打。

只有那種三個套件管理工具都沒有的機器要你動手。app 會直接把話說清楚：這台 Windows 伺服器上找不到 winget、scoop 或 cargo。請手動安裝 psmux，然後重新連線。 被精簡過的 Windows 安裝、或把 winget 移除的伺服器會落在這一段。自己抓 binary，放到 PATH 裡，再重連一次。

那樣裝完會在同一個資料夾留下三個名字：psmux.exe、pmux.exe、tmux.exe。在那台機器打 tmux，跑起來的是 psmux；psmux --version 也會先印一行 tmux 3.4.0，再印它自己的版本。沒有裝兩次。

在 Windows 的 session 裡能做什麼

  • session 不會因為斷線消失。列出來、建立、接回、改名、關一個、一次關好幾個都可以。Ctrl-b d 讓你回到 PowerShell 提示字元，Agentmux 的分頁也不會被關掉。
  • agent 跑在你的專案裡。從 C:\Users\you\src\app 這種 Windows 路徑啟動 Claude Code、Codex，或你自己的指令，目錄名字裡有空白也照樣走得通。
  • app 還是讀得到螢幕。那個 pane 是在等權限回答、在做事、還是空著，是從 pane 本身讀出來的。AI 自動權限審查在 Windows 上會真的把鍵按下去，不是只告訴你按哪一個。
  • 兩種 shell 都支援。Windows PowerShell 5.1 和 PowerShell 7，密碼或金鑰認證，磁碟機代號、UNC 路徑、目錄名字裡有空白。

跟 Linux 主機比，哪裡不一樣

  • 檔案走 SFTP。瀏覽、編輯、傳輸用的是 SFTP subsystem，不是 shell。如果你的 OpenSSH 安裝把 SFTP 關掉了，檔案功能會明講，不會默默失敗。Terminal 不需要它。
  • 檔案管理有兩個動作不給你用。跑 script 和 Git 操作在 Windows 上直接關閉，所以那台機器不會回你一段要自己解讀的 shell 錯誤。
  • 讀不到 pane 的目前目錄。psmux 沒有 pane_current_path，所以 app 沒辦法告訴你那個 pane 停在哪個目錄；回報執行中程式的那一列只會顯示 PowerShell。那一列更新也比 Linux 慢一點。
  • 附加的檔案落在暫存目錄。Linux 和 Mac 主機上，你附加的照片或檔案會進 /tmp；Windows 主機上會進 Windows 的暫存目錄。兩種情況打進終端機的路徑都是真的那一個。
  • Windows 是被連進去的那台。沒有跑在 Windows 上的 Agentmux。如果你的 Windows 只是你工作用的電腦，agent 住在別台，這一整篇跟你無關。

WSL2 還值得用嗎

有一個理由留下來了：你要的是 Linux 那個生態，有 apt、systemd、斜線路徑，而不是把一台 Windows 當伺服器。WSL2 裡面是完整的 Linux，這份指南 Linux 那條路的每一步都照樣適用。

三個坑也還在。WSL2 跑在 NAT 後面的一台虛擬機裡，所以那台 Windows 外面連不到裡面的 sshd，你要用 netsh interface portproxy 把 port 轉進去，或在 .wslconfig 開鏡像網路模式。最後一個程序結束後幾秒，發行版就關掉，要讓它常開得靠排程工作撐住。舊版預設沒有 systemd，而安裝精靈給的服務指令假設它有。

要跑 Linux 的程式，選 WSL2。要讓這台 Windows 變成你的伺服器，選原生那條路：裡面沒有虛擬機要維持開著，也沒有每次重開就可能變的 IP。

門開了，session 也活得下來。剩下的問題是手機上要打哪個位址，以及那個位址從外面連進來安不安全。
