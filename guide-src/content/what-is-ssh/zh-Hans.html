SSH 是你手上这台设备和另一台计算机之间的加密通道：你打的字送过去，那台机器执行，打印出来的文字带回来，中间经过的每一个节点都看不懂内容。要在手机上跑 agent，SSH 就是手机连到“agent 实际运行的那台机器”的那条路。

上一篇的结论是：agent 在终端里最能干活，因为它能读整个文件系统，也能真的执行命令。那个终端不必在你口袋里。它可以是家里那台从来没关过的 Mac mini，也可以是公司那台工作站，只要你的手机连得过去。

为什么是另一台机器，不是云端服务？

网页版 agent 和云端 IDE 也会让你连上一台机器。差别在那台机器是谁的。

SSH 连的是你自己那台。文件在那里，API key 在那里，你装过的包和设好的环境变量也都在那里。不用把任何东西搬到别人的服务器上，改动留在原地，事后不必再同步回来。

反过来也有取舍。如果你没有任何一台一直开着的机器，或是一整组人需要完全相同的起点，云端环境是更好的答案。换用自己的机器，代价是：它要一直开着、要连得到，而且设置由你负责。

连接要填的只有三样东西：host、user、port

每一次 SSH 连接都需要三个东西，命令把它们写在同一行：

ssh -p 22 sax@mac-mini
部分指的是什么
Host要连哪台机器：像 mac-mini 这种名称，或 100.101.102.103 这种地址
User那台机器上的哪个账号。你拿到的是那个账号的文件、权限和 shell，不会再多
Port那台机器上的哪扇门。SSH 默认是 22，所以这个字段通常留空

卡住的人多数卡在第一项和第三项。host 必须是手机真的路由得到的地址，下一节就在讲这件事。user 则必须真的存在于那台机器上：agent 以那个账号执行，它能碰到的东西，刚好就是那个账号能碰到的。

为什么不用 LAN 地址，也不用公网 IP？

你第一个找到的地址在网络设置里，长得像 192.168.1.23。先从同一个 Wi-Fi 下的笔记本试它，那正是它的用途。但它是路由器发出的私网地址，只在你自己的网络里有效。手机切换到移动数据就没有路能走到它，别人的网络也没有。

第二种是家里网络对外显示的公网地址，再在路由器上做端口转发，把那个端口指到这台机器。这条路走得通，也是要避开的那一条。扫描机器人对全世界的地址全天候尝试登录，一个对外开放的端口一天之内就会开始累积登录尝试。路由器的设置只要有一处错了，暴露出去的是整个网络，不是一台机器。

该用的是第三种地址：只有你自己的设备看得见的私有地址。Tailscale 会给每台机器一个 MagicDNS 名称或一个 100.x 地址，公网上没有别人知道它们存在。host 字段就填这个，在家和在外都一样。

密钥更安全，也更省事

SSH 收密码，也收密钥。这件事常被讲成安全和方便之间的取舍，但密钥两边都赢。

一对密钥就是两个小小的文本文件。私钥留在会发起连接的那台设备上。公钥由私钥算出来，复制到你要连的那台机器，放进那个账号 ~/.ssh 里的 authorized_keys。这条运算只有单向：公钥从私钥推得出来，反过来做不到。ssh-keygen 几秒就产生一对，剩下的都是复制粘贴。

登录时两半互相证明配对，你一个字都不用打。密码必须扛得住别人反复猜，密钥够长，猜没有用。设置一次，之后每一次连接都走同一套流程。

私钥最好加 passphrase（密钥口令），因为密钥就是一个文件。如果有人从一台没锁屏的笔记本上把它复制走，别人就握有你的密钥。加了口令，那个文件没有口令就毫无价值，而且口令跟账号密码不同：它从不过网络，只在本地解锁密钥。真正传出去的，是对一个挑战签好的短答案。

在手机上，这个差别更重要。打出来的密码每一次连接都要走过线路，任何摸得到那个端口的人都多一次猜的机会。密钥则是回答一个挑战，密钥本身从不离开你的设备。如果密钥都设好了还是被挡在外面，常见原因没几个：路径错、账号错、文件权限错。

App 把我的密码和密钥放在哪里？

Agentmux 不收集任何个人信息。使用统计是匿名、可选的，关掉它不会改变连接的方式。密码、密钥和口令都放进操作系统的硬件级凭据存储，不是普通文件。你的 SSH 流量不会被记录下来：那条通道在你的设备和你的机器之间加密，App 本身不是中继站。

第一次连接，为什么先问你信不信这组指纹？

连一台没连过的机器时，在密码或密钥之前，你会先看到一行说无法确认主机真实性的信息、一串十六进制字符，和一个 yes 或 no。那串字符是服务器的指纹，也就是那台机器签名用的 host key 浓缩出来的摘要。没有出错，这是 SSH 在验证另一个方向。

密码或密钥证明的是“你对那台机器来说是谁”，host key 证明的是“那台机器对你来说是谁”。少了 host key 这半边，任何一台站在你手机和家里 Mac mini 之间的设备，都能冒充那台机器回答，把你送出去的每一个字读走。第一次连接时你没有存过的指纹可以比对，所以 client 请你先信任它，然后从那之后记住这个值。

这一步在之后才派上用场。重新连一台指纹变过的机器，client 会直接拒绝。要么是你重装过系统，要么是有别的东西在代替它回答。

一定要把电脑架成服务器吗？

很多人听到 SSH 就想到机房和机柜。你要做的只是打开一个开关。Mac 上是“系统设置 → 通用 → 共享 → 远程登录”，Linux 上通常是启动一个叫 sshd 的服务，多数发行版默认就装好了。

开关打开之后，那台机器什么都没变。它还是你平时那台电脑，只是多了一扇可以从外面敲的门。不想记住顺序的话，设置页会问你三个问题，再按你的情况列出一张清单。

SSH 不是 VPN，也不是远程桌面

SSH 不做下面三件事：

它不是那样的话会是什么SSH 实际做什么
VPN你手机送出的所有流量都走进家里网络一条通道连到一台机器上的一个端口，其他东西不会因此连得到
挂载的文件系统远程的硬盘变成你能直接打开的文件夹需要时才搬字节：文件浏览器得自己一个文件一个文件去拉、去传
远程桌面你看到整个桌面画面，用手指去点双向都是文字：送出去的是按键，回来的是打印出的文字

最后一列是真的限制，不是这个工具的缺点。只存在于“一个可以点的窗口”里的软件，SSH 操作不了。上一篇画的是同一条界线：会用文字对话的 agent，才塞得进这条隧道。

然后你把手机收起来，隧道断了，agent 跟着死。除非那个 session 本来就不住在你的连接里面，那就是 tmux 负责的事。
