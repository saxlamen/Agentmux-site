AI 自動権限レビューは、画面を見ていないときにエージェントが出すコマンド許可プロンプトへ代わりに答える機能です。まずブラックリストが危険なコマンドを止め、許可リストが信頼済みのコマンドを通し、残りを AI 判定が判断します。最終的なキーの提案と自動押下の切り替えはセッションごとのモードで決まります。

作業の途中でエージェントが「このコマンドを実行してよいですか？」と止まることがあります。ちょうど席を外していると、キーを 1 つ押すだけの待ち状態で全体の作業が止まってしまいます。

AI 自動権限レビューはその瞬間のための機能です。プロンプトに対してキーを 1 回だけ答えます。コマンドを勝手に打ち込むことはなく、画面上の他の部分にも触れません。

エージェントが停止して待っているときだけ起動する

Agentmux はすでに Claude Code や Codex などの状態を追跡しています。「Allow this?」や「Pick 1 or 2」のようなプロンプトが画面に現れるとセッションが待機状態になり、そこからレビューが始まります。

動作には次の条件も満たしている必要があります。

  • 設定の「AI 自動権限レビュー」スイッチがオンであること。
  • セッションのモードが「オフ」ではなく「アドバイザー」または「自動応答」であること。
  • Pro プランを契約中、または無料トライアル期間中であること。

各プロンプトの判定は 1 回だけで、数秒おきに何度も再チェックすることはありません。レビュー中にユーザー自身がターミナルでキーを押したり文字を入力したりすると、進行中のレビューはキャンセルされてユーザー入力が優先されます。

別のタブに切り替えても、見ていない側のセッションではバックグラウンドでレビューが継続します。

スクロールバックではなく現在のプロンプトだけを読む

読み取るのは現在画面に表示されているプロンプト――実行しようとしているコマンド、質問文、提示された選択肢――だけです。上に流れ去った過去の出力は対象になりません。

画面内容を AI へ送る前に、Agentmux はパスワード、API キー、トークンに見える文字列をマスク（伏せ字化）します。マスク処理に失敗した場合はテキストを送信せず、キーも押しません。

ブラックリストは最初に端末内で動く

照合はすべて手元のスマートフォン上で行われ、他のどの判定よりも先に走ります。ブラックリストに一致したプロンプトは AI へ一切送られず、そのままユーザーへ渡されます。組み込みルールでは、特に危険性の高い操作をカバーしています。

  • /、~、またはホームディレクトリに対する rm -rf
  • sudo
  • git push --force（--force-with-lease は対象外）
  • DROP TABLE、DROP DATABASE、TRUNCATE TABLE
  • curl … | sh のようにダウンロード結果を直接シェルへパイプする操作
  • mkfs や dd if= などディスクへ直接書き込むコマンド

組み込みルールは編集・削除でき、独自のルールを追加することもできます。

許可リストは AI を使わずに決める

テスト実行やビルドのように毎日許可しているコマンドは、許可リストに追加しておくと次回からスマートフォン上で即決されます。端末内でキーを選ぶため、AI の応答待ちも API 利用料も発生しません。

「自動応答」モードでは、単一セッション限定で「このセッションのすべてのコマンドを許可」をオンにすることもできます。この場合 AI 判定はスキップされますが、ブラックリストは引き続き有効で、セッション終了時にこの設定は自動でオフに戻ります。

許可リストに一致しても、画面上に明確で安全な選択肢キーが見つからない場合はユーザーへ引き継がれます。

AI は何を基準に判断するのか

どちらのリストにも当てはまらなかったプロンプトだけが AI に届きます。AI にはマスク済みの画面テキストと、今回のタスクでエージェントにやってほしいことを表す Main Intent（例：「ログイン画面のテストを修正する」）が渡されます。

判定エンジンは 2 種類から選べます。

  • JEV 判定エンジン（OpenRouter または TypeSafe 経由）：ターミナルのプロンプト向けに作られた高速なエンジンです。3 段階で判断します。安全な読み取り専用操作は許可し、Main Intent に沿ったコマンドも許可します。無関係、不明瞭、または高リスクなものはすべてユーザーへ戻します。不審な内容や悪意あるインジェクションに見えるものは即座に拒否します。
  • OpenAI 互換 LLM：OpenAI、OpenRouter、または自分のマシンで動かしているローカルモデルを指定できます。

AI が出す結論は「許可」「拒否」「保留」の 3 択です。先へ進むのは「許可」だけで、AI は画面上のどのキーを選ぶか正確に指定する必要があります。「Always allow」や「Don't ask again」のような恒久的な許可は絶対に選びません。

アドバイザーは提案、自動応答は代理押下

モードはセッションごとに設定できます。

  • アドバイザー（既定）：提案のみを行います。画面上部に推奨キーと「適用」ボタンが表示され、タップするまで何も送信されません。
  • 自動応答：判定が「許可」のとき、代わりにキーを押し、どのキーを押したかを通知で知らせます。

どちらのモードでも、キーを送る直前に画面をもう一度確認します。プロンプトが変わっていたり、選択肢が移動していたり、カーソルが対象上にない場合は何も送りません。AI の判定には数秒かかるため、その間に画面が変わって誤ったキーを押してしまう事故を防ぐための二重チェックです。

自動応答でキーを送信したあと、そのセッションで次のキーを送るまで 3 秒の待機時間を設けています。

ユーザーへ引き継がれる条件

  • ブラックリストのルールに一致したとき。
  • AI が「拒否」または「保留」と判定したとき。
  • プロンプトがどのキーを求めているか判別できないとき。
  • 選択肢が「Always allow」などの恒久的な許可であるとき。
  • キーを送信する直前に画面が変化したとき。
  • 機密テキストのマスク処理に失敗したとき。

これらの場合は、レビュー機能をオフにしているときと同じ形でユーザーへ通知が届きます。

有効化の手順

始める前に、次のいずれかを用意してください。

  • OpenRouter または TypeSafe の API キー（JEV エンジン用）。
  • OpenAI API や手元のマシンで動かしているモデルなど、独自の OpenAI 互換 LLM エンドポイント。
  1. 「設定」→「AI 自動権限レビュー」を開き、スイッチをオンにします。初回は送信されるデータの説明が表示されるため、同意すると詳細設定へ進みます。
  2. 詳細設定でエンジンを選び、API キーを入力して「AI エンドポイント接続をテスト」をタップし、疎通を確認します。
  3. 設定画面に戻り、権限レビューモードの既定値（最初は「アドバイザー」が無難です）を選んで Main Intent を記入します。
  4. サーバーに接続してエージェントを起動します。新しいタブは既定モードで始まります。特定のセッションだけモードや Main Intent を変えたいときは、ターミナルツールバーの権限レビューボタンをタップします。ここで「最新のプロンプトを使用」をオンにすると、そのタブで送ったプロンプトが自動で Main Intent に反映されます。

まずは数日間「アドバイザー」で動かし、自分の実際の判断と提案が一致するかを確かめてから、パターンが安定しているセッションで「自動応答」に切り替えてください。

端末の外へ送信されるデータ

端末の外に出るのは「マスク済みの画面テキスト」と「Main Intent」の 2 つだけです。送信先はあなたが設定した AI サービスであり、あなた自身の API キーが使われます。「最新のプロンプトを使用」をオンにしている場合は、そのタブで送ったプロンプトが Main Intent になるため、それも送信対象になります。Agentmux 自体は AI サービスを提供も中継もしません。各判定の記録は端末内にのみ保存され、監査ログから確認・消去できます。モデルの推論過程は保存されません。
