可以，但 Claude Code 不会跑在你的 iPhone 上。它跑在你自己拥有的 Mac 或 Linux 机器上，手机只负责带着终端。做法是：打开远程登录，用 Tailscale 取代对外开放的端口，开一个有名字的 tmux session，在里面启动 claude。锁屏之后，agent 照样继续跑。

「在手机上跑 Claude Code」这句话听起来很直白，实际上讲的是两台机器、两种工作。把它们分开之后，问题都变短了：掉线之后什么还会活着、为什么同一条命令在 SSH 里找不到、agent 能不能在你坐地铁的时候自己回答权限提示。

Claude Code 是跑在手机上吗？

Claude Code 是你某台机器硬盘里的一个程序，由 shell 启动。它通过那台机器的文件系统读你的项目，跑 git，跑测试，把改好的内容写回同一个目录。很容易以为它有一部分现在住在你口袋里，但上面这些事没有一项发生在手机上。

从手机连过去，线路上只跑两样东西：你按的键出去，session 打印的字符回来。手机上没有装任何 agent 的组件，你的 repo 也不必搬到任何地方。手机显示的，只是另一台电脑上那个 session 现在的样子。

  • 手机上。按键、画面、你的拇指。锁屏、把应用划掉、走进电梯，停掉的只有画面。
  • 机器上。进程、正在被改的文件、正在跑的测试、它已经读过和决定过的一切。你的屏幕变暗，这一切都不会停。

有两个后果。机器必须一直开着、而且要连得到：合着盖子收在抽屉里的笔记本电脑什么都不会跑。手机那一边最便宜，换一部手机就恢复了。

先决定的三件事，顺序不能换

少任何一件都不成立，所以照这个顺序做。

  1. 一个进得去那台机器的门。Mac 上是「系统设置 → 通用 → 共享 → 远程登录」；Linux 上是 SSH 服务，一个叫 sshd 的 daemon。
  2. 一个私有网络，不要对外开放的端口。机器和手机都装 Tailscale，登录同一个账号，然后连那台机器的 MagicDNS 名称或 100.x 地址，不要连 192.168.1.23 这种局域网地址，因为手机切到移动网络之后，那个地址什么都不是。另一条路是把端口 22 转发到公网，那等于把机器摊在公网上，谁都能过来试你的密码。
  3. 一个有名字的 tmux session，而且 agent 在里面。
tmux new -s work     # 取名为 work
claude               # 在 session 里面启动

之后从手机、从另一个网络接回去的时候：

tmux ls              # 现在有哪些 session
tmux attach -t work  # 开一个窗口看进去

名字不是装饰：没有名字，你就没有可以指名要的那个 session，只敲 tmux attach 会接上最近的一个，那是在猜你的意思。机器上还没有 tmux 的话，Agentmux 会自己装。

只用一个 SSH 窗口，锁屏那一刻 agent 就死了

假设你跳过 tmux：从手机 SSH 进去，跑 claude，看它开始读项目，然后把手机放进口袋、锁屏。

手机不再发数据包，连接超时、关闭。机器上的 sshd 跟着关掉那条连接用的 pseudo-terminal，kernel 对还挂在上面的每一个进程发出 SIGHUP：你的 shell，还有 shell 里面的 Claude Code。它们默认的反应就是结束。agent 停在改到一半的地方，之前读了二十分钟的项目也一起没了。

让应用开着救不了它：Wi-Fi 换一个网络、移动网络断网、一个 Ctrl-C 按错地方，连接都照样断。tmux 把 session 从连接上搬到机器本身，所以你掉线时消失的是窗口，不是进程（机制在那篇 tmux 文章）。结论只有一条：agent 要在开始做事之前就在 session 里面，因为一个正在运行的进程没办法之后搬进去。

用手机工作实际上是什么样子？

手机适合一次只做一个决定，而 agent 的工作循环就是这样：它提出一个计划，你用一句话批准或打回；它问要不要顺便处理 migration，你选第二个。你回两行修正：「serializer 不要动，export 那边在用它」，然后把手机收起来。

屏幕键盘是第一笔真实的成本。backtick、pipe、引号、反斜杠、代表主目录的 tilde，全部藏在两层之后，所以 ~/src/auth/session.ts 这种路径打起来比想象中久，打错一段就是一个来回。长的 prompt 在手机上比较难写也比较难检查，很多人先在备忘录里写好，再粘贴进来。

读 diff 是手机真正不够用的地方：两个文件改了四十行，加上周围的 context，在六英寸屏幕上就是两三个屏幕的滚动；而且换行会让你看不出某个改动落在行尾还是行中，而那正是你要 review 的东西。把 iPad 横屏过来，同一个 diff 就不用换行。

一个马上回本的习惯：把吵的部分放进第二个 session，测试就不会盖掉 agent 自己的提示。

tmux new -s tests -d    # -d 创建后立刻 detach
tmux attach -t tests    # 看完再 detach

agent 可以自己回答权限提示吗？

Claude Code 不是想到什么就跑。它跑每一条命令之前都会先停下来；依照设置，改文件之前也会停。它把问题搁在屏幕上：这是它要跑的命令，可以吗？工作就在这里等，如果只有你能回答，要等多久就看你什么时候抬头。离开书桌之后，权限提示不再是不方便，而是整件事的瓶颈。

AI 自动权限审查只做这件事：读屏幕上当前那一则提示，然后给你建议、或帮你按下那个键。检查有固定的顺序。黑名单拦掉危险命令，命中的一定交给你。白名单放行你原本就信任的命令，直接在设备上决定，不用等。

AI 判断只处理两边都没命中的提示，结果是允许、拒绝或不确定，后两种一样交回给你。最后由这个 session 的模式决定，它是只建议按哪个键，还是直接帮你按。

人不在旁边，责任还是你的。一条在移动网络上批准的命令，跑在那台机器上，那里存着你的 .env、你的密钥，还有一个不只你一个人在用的 repo。AI 判断看到的是画面，它不知道 agent 为什么走到这一步。

所以先选只给建议的模式，把你每天都会批准的命令放进白名单；信号和注意力都不好的时候，先读屏幕上那条命令再按。黑名单之所以存在，是因为「全部批准」是个坏的默认设置，而且距离不会让它变安全：指向主目录的 rm -rf，不会因为你人在站台上就手下留情。

claude: command not found，但在 Terminal 里跑得好好的

同一台机器、同一个账号，两种结果：在 Terminal 里敲 claude 会跑，通过 SSH 就给你 claude: command not found。看起来像远程那套配置坏了，但这其实是从手机连进去最常撞到的问题。

Claude Code 如果是用 npm 装的，或是装在 nvm 固定的 node 版本底下，它的安装目录会写进一个启动文件。只有交互式 login shell 会读那个启动文件，PATH 里才有这个目录。ssh host claude 这种只跑一条命令的连接，启动的是非交互式 shell，它根本不会读那个文件。

最稳的做法是不靠 PATH。在原本跑得动的 Terminal 里：

which claude
# /Users/you/.nvm/versions/node/v20.11.0/bin/claude

把那个绝对路径整串当成 agent 命令，或直接敲在 session 里。nvm 换了 node 版本，这个路径就会失效。之后要更稳，得看你的 shell 和发行版，那些写在故障排查那页。

跑一整晚可以，重启不行

机器不休眠，session 就能跑一整晚：十一点丢一个重构给它，早上配着咖啡看结果。有三件事会卡住。

机器要维持清醒。Mac 闲置进入睡眠时，网络接口跟着休眠，远程登录开不开都没用，因为没有东西在响应。「系统设置 → 电池」（笔记本电脑）或「系统设置 → 节能」（长期开机当服务器用的台式机）：把闲置睡眠的时间调长或关掉，有「唤醒以供网络访问」这个选项就打开。

重启会把 session 一起带走。tmux 不会在重启之后还原 session，系统更新要重启时也不会问你。收工之前先 commit，最坏的情况就从损失整个任务变成损失一个小时。

在等你的 agent 不是卡死的 agent。先接回去看一眼。一个全新的 shell 提示符代表进程已经结束，跑完了或是死了，上面几行会告诉你是哪一种。另一个 session 如果停在一个问题上，它已经等你一个字等了六小时，也没花掉什么。从锁屏看，这两种一模一样，而且只有一种需要你动手。

什么归手机，什么归书桌

在手机上做在书桌前做
读完那条命令之后回答权限提示看一段你没预期会看到的 diff
在它给的两个做法之间选一个判断一个横跨好几个文件的改动
读一段短的 diff、commit、push读一段长的 diff，或一个你没打开过的文件
在第二个 session 里看测试跑完追那些测试打印出来的失败
睡前把下一个任务丢给它写一段必须很精确的 prompt
连接断了十次，再接回来修连接本身，或它后面的 PATH 问题

三样东西：一台不会休眠的机器、一个有名字的 session、一条只有你进得去的路。少一样，setup 那页会先问你三个问题，再照你那台机器给一份清单。
