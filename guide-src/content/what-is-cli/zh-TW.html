「CLI」聽起來像一種懲罰。沒有滑鼠、沒有按鈕，只有一個閃爍的游標。但這幾年最強的 coding agent 全都住在這裡——Claude Code、Codex，一個不缺。

不是因為做 CLI 的人比較硬派。是終端機給了它們別的介面給不了的東西：完整的檔案系統存取與執行權限。

終端機到底是什麼

終端機只做兩件事：接受你打進去的文字，把結果印回螢幕。沒有圖層，沒有按鈕。進去是字元，出來也是字元。

簡單到這個程度，agent 才操作得動。它打的每一行指令跟你手動打的沒有兩樣。它看到的錯誤訊息，跟你會看到的一字不差。

能力邊界，不是介面美醜

網頁版的 agent 看不到你電腦裡的任何一個檔案，它只活在瀏覽器分頁裡。IDE 外掛看得到你打開的檔案，但通常卡在「建議」層級——改不動 git，跑不動測試，更別說裝套件。

CLI agent 拿的是你自己打指令時那組權限。能讀整個 repo，能下 git commit，能跑測試套件，能裝依賴。Claude Code、Codex、Gemini CLI、OpenCode 全是這一類：能對整台機器下指令的 agent，不是困在沙盒裡看得到動不了的旁觀者。

這個差別沒有廠商刻意設計來討好誰。選了終端機當介面，這組權限就跟著來了。

一個具體的樣子

你丟一句「把這個 bug 修好」。agent 讀相關檔案、改 code、下 npm test、看到某個測試還是紅的、回頭再改、再跑一次。直到全部綠燈。全程你沒點過一個按鈕。

這條迴圈跑得完，靠的就是終端機那組執行權限。換成網頁版或 IDE 外掛，它在第二步就卡住，等你回來按下一步。

這些 agent 可以跑在別台機器上。前提是你連得過去。
