你的 Windows 电脑也可以当主机

支持。Agentmux 可以直接用 SSH 连一台原生 Windows 电脑，里面不必装 Linux。打开 Windows 10 或 11 自带的 OpenSSH Server，把那台机器加进来，你拿到的是 PowerShell 终端、靠 psmux 撑住的持久 session，还有你的 coding agent。

过去的标准答案是「先塞一个 WSL2」。理由只有一个：少了 tmux，手机一掉线，agent 跟着死。现在有一个为 Windows 写的程序补上这个位置，WSL2 就从必经之路变成你可以选的路。

那台 Windows 上要准备两样东西

第一样是一扇 SSH 的门。Windows 10 和 11 都把 OpenSSH Server 做成可选功能，用 PowerShell 以管理员身份装一次：

# PowerShell，以管理员身份运行
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
Start-Service sshd
Set-Service -Name sshd -StartupType Automatic

安装过程会自动加一条名为 OpenSSH-Server-In-TCP 的入站防火墙规则。如果你的机器防火墙比较严，先检查那一条。第二行现在就把服务开起来，第三行让它重启之后还在。这条在 Windows 上比在 Mac 上要紧，因为 Windows 会自己决定什么时候更新重启。

第二样是 multiplexer。Agentmux 会先问那台机器是什么系统，Windows 的答案不一样，所以应用走另一条路：自己的命令改用 PowerShell 而不是 sh -c，路径用盘符而不是斜杠，multiplexer 用 psmux 而不是 tmux。这一切都是应用自己判断，你不用找开关。你的登录 shell 是 PowerShell 还是 cmd.exe，它也不在意。

为什么是 psmux 不是 tmux

psmux 是另一个程序，命令行照 tmux 的设计：session、window、pane、send-keys、capture-pane 都有，还会顺便装一个 tmux.exe 的别名，手上的按法不用改。Agentmux 依次找 psmux、pmux、tmux.exe，找到哪个就用哪个，所以那台机器早就装过就不会动它。

它不是 tmux 的移植版，也没有假装自己是。应用会看那个程序实际返回什么，而不是看版本字符串，缺的功能就干脆不用。下面那份「哪里不一样」的清单就是这样来的。

想知道为什么非要有这个程序，这篇讲得很短：连接断开，shell 收到 SIGHUP，没有 multiplexer 的 agent 就跟着走了。

没装 psmux 会怎样

应用会帮你装。它先试 winget install -e --id marlocarlo.psmux，没有就试 Scoop，再没有就试 cargo install psmux，用机器上有的那个装完再重连。手机这边你什么都不用敲。

只有那种三个包管理工具都没有的机器要你动手。应用会直接提示：这台 Windows 服务器上找不到 winget、scoop 或 cargo。请手动安装 psmux，然后重新连接。 被精简过的 Windows 安装、或把 winget 移除的服务器会落到这一段。自己下载 binary，放到 PATH 里，再重连一次。

那样装完会在同一个文件夹留下三个名字：psmux.exe、pmux.exe、tmux.exe。在那台机器敲 tmux，跑起来的是 psmux；psmux --version 也会先打印一行 tmux 3.4.0，再打印它自己的版本。没有装两次。

在 Windows 的 session 里能做什么

  • session 不会因为掉线消失。列出来、创建、接回、改名、关一个、一次关好几个都可以。Ctrl-b d 让你回到 PowerShell 提示符，Agentmux 的标签页也不会被关掉。
  • agent 跑在你的项目里。从 C:\Users\you\src\app 这种 Windows 路径启动 Claude Code、Codex，或你自己的命令，目录名字里有空格也照样走得通。
  • 应用还是读得到屏幕。那个 pane 是在等权限回答、在做事、还是空着，是从 pane 本身读出来的。AI 自动权限审查在 Windows 上会真的把键按下去，不是只告诉你按哪一个。
  • 两种 shell 都支持。Windows PowerShell 5.1 和 PowerShell 7，密码或密钥认证，盘符、UNC 路径、目录名字里有空格。

跟 Linux 主机比，哪里不一样

  • 文件走 SFTP。浏览、编辑、传输用的是 SFTP subsystem，不是 shell。如果你的 OpenSSH 安装把 SFTP 关掉了，文件功能会明讲，不会默默失败。Terminal 不需要它。
  • 文件管理有两个操作不可用。运行 script 和 Git 操作在 Windows 上直接关闭，所以那台机器不会给你返回一段要自己解读的 shell 错误。
  • 读不到 pane 的当前目录。psmux 没有 pane_current_path，所以应用没办法告诉你那个 pane 停在哪个目录；汇报运行中程序的那一栏只会显示 PowerShell。那一栏更新也比 Linux 慢一点。
  • 附加的文件落在临时目录。Linux 和 Mac 主机上，你附加的照片或文件会进 /tmp；Windows 主机上会进 Windows 的临时目录。两种情况打进终端的路径都是真的那一个。
  • Windows 是被连进去的那台。没有跑在 Windows 上的 Agentmux。如果你的 Windows 只是你工作用的电脑，agent 跑在别的机器上，这一整篇跟你无关。

WSL2 还值得用吗

有一个理由留了下来：你要的是 Linux 那个生态，有 apt、systemd、斜杠路径，而不是把一台 Windows 当服务器。WSL2 里面是完整的 Linux，这份指南 Linux 那条路的每一步都照样适用。

三个坑也还在。WSL2 跑在 NAT 后面的一台虚拟机里，所以那台 Windows 外面连不到里面的 sshd，你要用 netsh interface portproxy 把端口转进去，或在 .wslconfig 开镜像网络模式。最后一个进程结束后几秒，发行版就关掉，要让它常开得靠计划任务撑住。旧版默认没有 systemd，而配置向导给的服务命令假设它有。

要跑 Linux 的程序，选 WSL2。要让这台 Windows 变成你的服务器，选原生那条路：里面没有虚拟机要维持开着，也没有每次重启就可能变的 IP。

门开了，session 也活得下来。剩下的问题是手机上要输哪个地址，以及那个地址从外面连进来安不安全。
