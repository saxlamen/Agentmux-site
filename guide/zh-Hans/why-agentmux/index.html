为什么不是 Termius / Blink

通用的 SSH 应用假设你打开它是为了敲命令；Agentmux 假设你是要接回一个已经在运行的 agent。需要 Mosh、SOCKS5 转发，或跨平台同步主机列表，就买 Termius 或 Blink。如果你整天在好几台服务器的 agent 之间切换，就买 Agentmux：一个赢在范围，一个赢在接回的深度。

两个都能开 SSH、都能敲命令，分叉的地方只有一处：谁把「接回」这件事想得比较透彻。下面每一条差别都是从那个假设来的，所有功能全部对照现行代码查证过。

两种工具的核心假设不同

通用的 SSH client 围绕的是「一台主机加一个 shell」：给你一个能用的提示符，然后别挡路。提示符之后发生什么是你的事：你开哪个进程、它活不活得下来、明天怎么找回来。

Agentmux 围绕的是「一个已经在运行的 agent」，它的任务是缩短你口袋到那个进程的距离。三个结论随之而来，后两个是通用的 client 补不起来的地方。原因不是它做得比较差：那些行为本来就不在它的产品范围内。

  • 你先看到什么。一台主机，或这台主机上跑着的 session。
  • 掉线的代价。一个要自己重新来过的提示符，或你离开时的那个画面。
  • 你不在的时候应用做什么。什么都不做，或锁屏上的进度，加上一声跑完的提示音。

为什么先列 tmux session？

连上服务器，Agentmux 直接把上面现有的 tmux session 列出来，点一下就接回去。不用记 tmux ls、tmux attach -t。掉线之后重连，接的还是同一个 session，画面停在你离开的那一刻，不用重新敲一次 attach。

agent 的价值在于它积累下来的上下文：读过哪些文件、为什么选这个做法。接回同一个画面，上下文还在眼前；开一个新的提示符，你得对一个已经忘光的进程把任务重讲一次。如果你还没用过 tmux，先读tmux 在做什么，这整套设计都建立在它上面。

你不在的时候，应用在做什么？

agent 常常一跑就是几十分钟，这个功能就是为那段等待做的：灵动岛和锁屏显示当前进度，跑完可以播一声提示音。应用不必一直开在前台，让你死盯着等结果。

围绕 shell 的应用关掉之后没有东西可汇报，因为它没有「还在跑」这层概念。这边是某台服务器上某个有名字的 session 在跑，系统的面板替它汇报。等它停下来问你要不要允许某条命令时，AI 自动权限审查可以先替你看一眼：危险的拦下来，安全的给建议或直接帮你按（Pro）。

在手机上改文件或传截图，一定要开 vim 吗？

临时改一行代码，不必在手机上跟 vim 肉搏。内置的 Runestone 编辑器直接打开文件让你改。要看 agent 产出的 README，Ink 提供双栏 Markdown 预览，源码和排版同时看得到。快捷栏的添加附件按钮可直接拍照、从照片或文件 App 选取或粘贴剪贴板图片，通过 SFTP 上传并把远程路径自动输入终端交给 agent 查看。Git 工具（切换分支、查看 diff）、文件历史和 Files 应用集成是 Pro 功能，14 天试用期间也用得到。

重点是不用换设备就能走完这一轮：你把截图传给 agent、看 diff、回答它，它继续跑。每多一个步骤要换到另一台机器，你就多跑一趟书桌。

你的私钥放在哪里？

私钥在 iOS 只存在系统的 Keychain 里，在 Android 则由 Android Keystore 做硬件保护，不会写入本地数据库。如果你开了 iCloud 同步（iOS），CloudKit 带走的是服务器名称这类不敏感的 metadata。私钥留在原地。

考虑任何工具都问同一个问题：开了同步之后，我的哪些私钥会离开这台设备？功能列表不会回答你。

Siri 可以把终端画面交给快捷指令

对 Siri 说「从 Agentmux 获取当前终端内容」，GetCurrentSessionContextIntent 就把终端当下的内容抓进 iOS 快捷指令，可以接去备忘录、信息，或任何你自己搭的流程。ContinueLastSessionIntent 更直接：一句「在 Agentmux 继续工作」就接回上一个 session。

这类自动化，通用的 SSH 应用从结构上做不到：它们没有 session、项目、agent 这一层语义模型可以交给系统。Agentmux 目前实现了 10 个 App Intent，涵盖 Server、Project、TMUXSession、RecentSession 四种 entity。

三个专门针对中文体验的修复

1.3.10 修掉了三个英文圈用户感觉不到、中文读者一眼就懂的毛病：全角字符选中时对齐跑偏，链接跨行时复制出来断成好几截，词句里出现一个斜杠就被当成文件路径。没有实际处理过中日韩文字的人，不会踩到这三个坑。

你的工作是哪一种，就买哪一种

主要是一台主机上的手动终端工作。你登录是为了跑自己挑的命令：重启服务、tail log、看磁盘。那就买通用的 SSH client。想先试试以 session 为中心的做法，免费的单服务器方案就涵盖一台服务器、持久 session 和核心终端。

整天住在好几台服务器的 agent 里。一个在 Mac mini 上重构，另一个在 Linux 机器上跑测试，第三个是你上火车前开的。这就是 Agentmux，而且具体来说是 Pro：多服务器、自定义 agent、远程编辑、文件历史、分支工具、批量操作。

agent 活在浏览器标签页或云端沙盒里。方便是真的，代价是文件和凭据不再存在你的机器上。Agentmux 从不代跑你的工作：它是 client，代码和 agent 留在你自己拥有的硬件上，一台 Mac、一台 Linux 机器、或一台服务器。把项目和密钥放到别人租给你的环境里，只要你觉得安心，那也是合理的选择。

怎么连进去跟选哪个应用一样重要。标准 SSH 加密钥或密码就够，建议走 Tailscale，因为不用对公网开端口。地址要用 MagicDNS 名称或 100.x 地址，不是局域网 IP。

什么时候该买 Termius 而不是 Agentmux

下面任何一条如果是你的主要工作，就去买通用工具。

  • 你在很不稳定的移动网络下工作，需要 Mosh 撑住连接。Agentmux 只有标准 SSH，靠 tmux 自动重连补回来，但那不等同于 Mosh。
  • 你需要 Remote／Dynamic（SOCKS5）port forwarding。Agentmux 只有 Local。从某个网络打隧道出去、或让浏览器走跳板机，是你每天在做的事。这样的话，这是硬缺口，不是偏好问题。
  • 你要在 iOS／Android／Windows／macOS／Linux 之间同步大量主机配置，或跟团队共享主机列表。Agentmux 是手机与平板的 client：Pro 有多服务器与批量操作，没有共享给同事这回事。
  • 你是 SRE 或系统管理员，要在几十上百台服务器上做运维。能被脚本操作的主机列表，胜过一个要你点来点去的 session 列表。

Agentmux 为一个工作流设计：在手机上接回正在运行的 coding agent。它不是通用的运维工具。如果你一周的工作就是一条一条零散的命令，这些差别对你没有价值。

iPad 外接键盘 vs iPhone 碎片时间

如果你常带着 iPad 和实体键盘、在高铁或弱 Wi-Fi 下长时间直接在远程 shell 写代码，Blink 或 Termius 的 Mosh 会更重要；如果你多半是用 iPhone 在离开桌面后查看进度、回复 Claude Code 或 Codex 的确认提示、顺手看几行 diff，以 session 为中心、点一下就接回的设计最省步骤。

决定用 Agentmux？下一个问题是连接另一头那台机器。配置向导问三个问题，然后给你一张检查清单；之后常见的毛病，故障排查已经都写在那里了。
