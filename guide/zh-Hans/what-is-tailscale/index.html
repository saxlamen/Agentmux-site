不要对公网开端口

在家里的电脑和手上的手机都安装 Tailscale，两边登录同一个账号，接着 SSH 连接时填那台机器的 MagicDNS 名称或 100.x 开头的地址。Tailscale 在你自己的设备之间建立 WireGuard 加密 mesh，所以不需要对公网开放任何端口，也不需要一个固定的公网地址。

agent 在你关掉手机之后还能继续跑，但光是这样还不够，你得先有一个安全的入口可以连回去。最直觉的做法是把家里的 22 端口开到公网，而那也最快出事：扫描机器人对全世界的地址全天候敲 22 端口，失败的登录记录不到一天就会堆起来。

第二个问题比较无聊，也更难避开。你家的对外 IP 几乎一定是动态的，每隔一阵子换一次号码；机器又躲在 NAT 后面，跟家里其他设备共用那一个对外地址。那里本来就没有公网地址可以开。

传统解法是路由器上的三件事

以前的做法是自己进路由器打通：端口转发把公网某个端口转给家里那台机器，DDNS 把主机名称绑定到当下那个 IP，或是向 ISP 买固定 IP，然后自己维护防火墙规则，挡掉除你以外的每一个人。

每一步都要对。错一步，要么连不进去，要么整个家用网络暴露在外。就算全部设置正确，那扇门也永远开在公网上，你在不在家都一样。

端口转发加动态 IP 为什么一直出问题？

这里有四个会动的零件，每一个都可以在最不方便的时候松掉。

  • 地址会变。ISP 重新连接就换号码，DDNS 客户端要几分钟才跟上。每次换号码之后都有一段时间，你存好的那个名称连不回家；如果那次更新发生在你出门时，名称从此指向别人的网络。
  • 那个地址常常不是你的。躲在运营商级 NAT 背后时，路由器只拿到 ISP 内部网络的一个地址，端口转发因此完全无效：对外那个地址属于 ISP，而且是好几个用户共用。
  • 多一个转发就多一扇门，门后面是家里的网络，里面有智能电视，也有旧摄像头。
  • 它必须永远正确。固件更新会清掉规则，换路由器要把规则全部重建，机器换了局域网地址，转发就指向空处。

最麻烦的是出错那一刻：你在地铁站台上，用移动网络的手机去检查家里的路由器，而你要连的东西刚好连不到。

Tailscale 做了什么？

Tailscale 是一个 WireGuard mesh。每台设备都装好、都登录同一个账号，设备之间就会直接建立一条加密连接。这么做没有一个对外入口，公网上也没有端口等着被扫描。

每台设备产生一对 WireGuard 密钥，私钥那半从不离开设备。公钥拿去互相交换，交换完成，隧道就建立了。账号那一侧是账务工作：让设备彼此认识、记下每台设备现在从哪里连得到、发出公网不会路由的私有地址。

MagicDNS 给每台设备一个你记得起来的名称，名称解析由 Tailscale 自己处理，你不用碰那个会变的 IP。设备在 NAT 后面、地址昨晚换过、从家里的 Wi-Fi 切到移动网络，这些变化它在背后就处理好了。

手机也在 NAT 后面，mesh 为什么还行？

移动网络让问题更糟。手机也没有可以被连进来的公网地址：在 4G、5G 之下，它躲在运营商级 NAT 后面，跟大量用户共用同一个对外地址。所以靠别人从外面敲门的做法，两端同时失效。

mesh 是反过来的设计：两边都只需要往外发数据包。手机发一个，机器发一个，双方各自知道对方看起来在哪里，再试着穿过自己的 NAT 开出一条直连。加密由 WireGuard 负责，介绍由 mesh 负责。找不到直连时，流量改走中继站，连接不会断，也仍然是端到端加密。

你的机器多了一个只有你连得到的地址

你家那台机器多了一个私有地址。只有登录同一个 Tailscale 账号的设备看得到它、连得到它。扫描机器人不知道它存在，因为它从没出现在公网上，而你的路由器什么都没改。

从这里开始，你的 SSH 连接打的就是这个地址，不再是那个天天被人敲门的 22 端口。

你该填的是哪个地址？

局域网那个不是答案。同一台机器在这个架构下同时有三个地址，只有两个值得存进 app。

地址在哪里连得到要不要用
局域网地址，例如 192.168.1.23 只有那个 Wi-Fi 底下 不要。手机切到移动网络就没有路走到它
ISP 给路由器的地址 运营商级 NAT 之下哪里都不通 不要。它会变，而且是路由器的
MagicDNS 名称，例如 mac-mini.tail1234.ts.net 任何网络，两端隧道都开着就行 要。存这个
100.x.y.z 跟名称一样 留一组，名称解析坏掉时用

局域网地址代表的是那个局域网，不是你那台机器。只要存名称，机器换 Wi-Fi、换 IP、甚至搬家，你都还连得到。在机器上打 tailscale status，两个值都会列出来。

两台设备看起来都已经连接，SSH 却还是失败的话，先查你填的那个地址。Tailscale 显示已连接，SSH 仍连不到那一节写了完整的顺序，包括机器被注销、需要重新登录的情况。

这样做你要付出什么？

有三笔成本，最好在你挤进地铁之前就知道。

机器上多一个常跑的程序。它随开机启动、偶尔自己更新、也有自己的 bug。机器连不到的时候，要多排查一个嫌疑犯，才轮到 SSH。

多了一个控制面，而你在最坏的时刻需要它。流量直接走设备对设备，但设备之间的介绍不是这样。新的笔记本、刚换掉的手机、过期的凭据，在它们重新登录之前都不在你的网络里。如果那次重新登录发生在你出门时，机器好好的，你就是连不到。另外留一条不经过它的进入方式。

手机必须维持连接。手机上那条隧道是一个 VPN profile，手机会把它关掉：重启之后、别的 VPN 接手之后、还有你点掉那个请求的时候。排查之前先确认它还开着。它只承载连往你自己那些地址的流量。

私人网络不是改回密码的理由

有一个看起来合理的推论：公网连不到的机器，门上不必上锁。这个推论错了，那台机器还是要上锁，而且有两个理由。

mesh 的安全现在就是账号的安全。任何能登录的设备都在网络里面，也就是多了一台你已经信任的设备。忘在出租车上的笔记本不是掉在公开的 Wi-Fi 上，是在你自己建的网络里面，每台机器都连得到，也没有别的东西拦它。密钥的好处是那一台设备还是得证明自己是谁，才走得到下一步。

第二个理由是多一层防线：mesh 让外面的人进不来，密钥让已经在里面的陌生人走不下去。两件独立的事情都失效，才会有人动到你的项目。密码是一个猜得中的东西，密钥不是。密钥怎么完成证明，写在 SSH 那一篇。

什么时候不需要 Tailscale？

如果机器和手机永远都在同一个 Wi-Fi 底下，跳过这一步。局域网地址就能用，不用装东西，也不用登录账号。缺点是你一走出家门就全部失效，而这篇处理的正是出门之后。

自己租的服务器是另一种情况。地址不会动，没有路由器要设置，玩坏了也不会把自己锁在外面。换过来的风险是 22 端口永远面对公网。有人还是会在上面跑 mesh，把 SSH 收到私有地址后面；有人让它维持公开，完全依赖密钥。两种都可行，不可行的只有一种：暴露在公网上的端口用密码登录。

如果你已经通过别人管理的网络连到那台机器，例如公司的 VPN，就走那条路。两条重叠的隧道不会让你更容易连上，只会让排查更难。如果你不确定自己属于哪一种，设置页会问三个问题，然后回给你一张排好的清单。
