15 minutes to an agent that works all night

Answer three questions and I'll give you a checklist built for your setup. Every step tells you why you're doing it, what the command is, how to confirm it worked, and where to look if it didn't. (Is that machine running Windows? Read this first.)

Using Windows?

You picked Windows above, which is why the wizard didn't hand you a checklist — not because one is missing, but because this path is a different shape from the other three, and half a checklist would do you more harm than none. The short version: it works, but it has to go through WSL2, and it takes a few more steps than a Mac or a Linux box. If your goal is simply to get an agent working through the night as soon as possible, renting the cheapest cloud VPS you can find and following the VPS path above is usually faster than getting Windows there — that's not a brush-off, it genuinely saves most people time.

Why native Windows won't do

This guide rests on three pieces: the CLI, tmux, and SSH. SSH is a non-issue — Windows 10 and 11 both ship an OpenSSH Server you can switch on, and you'll be able to connect and get a PowerShell prompt.

The problem is tmux: there is no native Windows build, and tmux happens to be the load-bearing piece of this whole guide. Without it, the moment your connection drops the agent gets SIGHUP and dies with it (here's the mechanism), and "put your phone away and it keeps running" — the central promise here — stops being true. You'd end up with a Windows machine you can SSH into, but not the thing this guide is actually offering.

As for whether the agents themselves run on Windows: support varies by tool and changes quickly, so there's deliberately no list here — check the official documentation for the one you plan to use. But note the order of the argument: even if your agent runs perfectly on native Windows, the tmux problem above is unchanged. Whether an agent can run and whether it survives a disconnect are two different questions.

The recommended route: WSL2

Inside WSL2 you have a complete Linux, and tmux, sshd, and the agents all behave the way they do on real Linux. Once a distribution is installed, every step of the "Linux box" path above applies — you can go back up and answer the first question as a Linux box.

Three snags that don't exist on Mac or Linux

None of these is a dead end, but they're worth knowing in advance so you don't assume you've made a mistake somewhere:

  • Networking. WSL2 runs in a virtual machine with its own IP, behind NAT, so the sshd inside it isn't reachable from outside that Windows host by default. Two ways around it: set up netsh interface portproxy on the Windows side to forward the port in (though WSL's IP can change on every restart, so you'll be redoing it), or turn on mirrored networking with networkingMode=mirrored in .wslconfig, which lets WSL share the host's network interfaces and removes the port-forwarding step entirely. The second is much cleaner but needs a reasonably recent Windows 11.
  • WSL doesn't stay running on its own. Once the last process exits, the distribution shuts down within seconds and the virtual machine goes with it. But this guide wants a machine that's always on — you need WSL to start at boot and stay up even with nobody logged in, which usually means a scheduled task or a keepalive. On a Mac or a Linux box this simply isn't a thing you have to think about; it's specific to WSL.
  • systemd is opt-in. Older WSL has no systemd at all — the systemctl command doesn't exist — so the systemd commands in the wizard's "enable the SSH service on the Linux box" step will fail outright. Newer versions can turn it on with systemd=true in /etc/wsl.conf, but it's off by default and older installations won't have it.

One more option: keep Windows as the client

Worth being explicit about: the Windows discussed here is always the machine you connect to. If your Windows PC is just the computer you use day to day, and the machine that runs the agent is something else — a Mac mini at home, a Linux box at the office, a VPS — then none of the above applies to you. This guide works for you exactly as written, because the machine you actually need to set up was never the one in front of you.
