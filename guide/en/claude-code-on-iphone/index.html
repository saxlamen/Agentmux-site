Run Claude Code on your iPhone or iPad

Yes. Claude Code is a program that runs on a machine you own, never on the phone. Turn on Remote Login, reach that machine through Tailscale instead of an open port, start a tmux session with a name, and run claude inside it. Your iPhone carries a terminal; the agent keeps working after you lock the screen.

The phrase sounds obvious and is not: "Claude Code on my phone" describes two machines doing different jobs. Separate them and what is left gets short — what survives a dropped connection, why the command is missing over SSH, whether an agent should answer its own permission prompts from a train.

Your phone carries a terminal. That is all.

Claude Code is a program on the disk of some machine you own. A shell starts it. It reads your project through that filesystem, runs git and the tests, and writes its edits back into the same directory. The misconception: that some part of it now lives in your pocket.

From the phone, two things cross the wire: keys go out, characters come back. Nothing of the agent is installed there, and no copy of your repository travels. The phone draws a picture of a session living on another computer.

  • On the phone. Keystrokes, display, your thumb. Lock the screen or swipe the app away and the display stops; that is the whole list.
  • On the machine. The process, the files being edited, the tests, everything already read and decided. None of it notices your screen going dark.

Two consequences. The machine has to stay on and reachable — a laptop in a drawer with the lid shut runs nothing. The phone is the cheap half to replace.

Three things in place, in order

Skip one and the arrangement fails. Do them in this sequence.

  1. A door into the machine. On a Mac: System Settings → General → Sharing → Remote Login. On Linux, the SSH service, a daemon called sshd.
  2. A private network, not an open port. Install Tailscale on the machine and the phone, sign both into one account, then connect to the MagicDNS name or the 100.x address — never a LAN address like 192.168.1.23, which means nothing on mobile data. Forwarding port 22 instead hands your machine to every scanning bot that finds it.
  3. A tmux session with a name, and the agent inside it.
tmux new -s work     # name it
claude               # inside it

From the phone, on another network:

tmux ls              # what exists
tmux attach -t work  # open a window onto it

The name matters: tmux attach alone takes the most recent session. If tmux is missing, Agentmux installs it.

Why a plain SSH window kills the agent

Skip tmux: you SSH in, run claude, then pocket the phone and lock the screen.

The connection times out and closes. sshd closes the pseudo-terminal it was attached to, and the kernel sends SIGHUP to every process still on it — your shell, and Claude Code inside it. The default response is to terminate: the agent dies mid-edit, twenty minutes of reading gone.

Keeping the app open fixes nothing: Wi-Fi switches networks, cellular loses signal, one Ctrl-C lands wrong. tmux moves the session onto the machine, so what disappears is the window, not the process (the mechanism). The rule: the agent goes inside the session before the work starts — a running process cannot be moved into tmux afterwards.

What working from a phone is actually like

What fits a phone is one decision at a time — which is what an agent cycle is made of. It proposes a plan; you take it or send it back in a sentence. A two-line correction — "leave the serializer alone, the export job uses it" — and the phone goes away.

The on-screen keyboard is the first real cost. Backticks, pipes, quotes, backslashes and the tilde all sit two layers deep, so ~/src/auth/session.ts takes longer than it should and one wrong segment costs a round trip. Long prompts are harder to proofread than they look, so many people draft them in a notes app.

A diff is where a phone runs out of room: forty changed lines across two files is three screens of scrolling on six inches, and a wrapped line hides whether a change sits at the end of a line or in the middle. Turn an iPad sideways and it fits without wrapping.

One habit pays for itself: a second session for the noisy parts, so a test run cannot bury the agent's prompts.

tmux new -s tests -d    # -d starts it detached
tmux attach -t tests    # watch it, then detach

The agent stops and asks. From the phone, you answer.

Claude Code does not run everything it thinks of. Before it runs a command — and, depending on configuration, before it edits a file — it stops and asks: here is the command, go ahead? That stop is where the job waits, and when only you can answer it, the waiting becomes the bottleneck.

AI Permission Review answers those prompts and nothing else: it reads the prompt, then suggests or presses the key. A blacklist blocks dangerous commands and always hands a match to you. An allowlist passes commands you already trust, decided on the device. Anything matching neither goes to an AI judgement: allow, deny, or unsure, and the last two come back to you. The session's mode then decides whether it only suggests the key or presses it.

Distance does not transfer the responsibility. A command approved on cellular runs on a machine holding your .env, your keys, and a repository you do not own alone — and the judgement sees the screen, not the reasoning that got the agent there. Start in the mode that only suggests, allowlist the commands you approve daily, and read the screen before pressing anything when signal and attention are poor. The blacklist exists because "approve everything" is a bad default: an rm -rf aimed at a home directory is no gentler because you said yes on a platform.

claude: command not found, but it runs in Terminal

Same machine, same account, different answers: claude starts in Terminal and prints claude: command not found over SSH. It reads as the remote setup being broken, and it is the most common failure on the way in.

The cause, in two sentences. An install through npm, or under a node version nvm pins, puts its directory on the PATH from a startup file that only an interactive login shell reads. A connection running one command, like ssh host claude, starts a non-interactive shell that never reads that file.

The fix that always works is to stop relying on the PATH. In the Terminal where it runs:

which claude
# /Users/you/.nvm/versions/node/v20.11.0/bin/claude

Use that absolute path, as the agent command or typed into the session. It breaks when nvm changes the node version; the durable fix, which depends on your shell and your distribution, is on the troubleshooting page.

Overnight works. A reboot does not.

A session on a machine that stays awake runs all night — hand it a refactor at eleven, read the result with coffee. Three limits.

The machine has to stay awake. A Mac that idles into sleep takes its network interface with it, and Remote Login makes no difference: nothing is left to answer. System Settings → Battery on a laptop, Energy Saver on a desktop: lengthen or switch off idle sleep, and turn on "Wake for network access" if offered.

A reboot takes the session with it. tmux does not restore sessions after a restart, and updates restart without asking. Commit before you stop for the night, so the worst case costs an hour.

Waiting is not crashing. Attach and look. A fresh shell prompt means the process exited: finished, or died, and the lines above say which. A prompt asking a question has waited one word from you for six hours at no cost. From a lock screen both look the same; only one needs you to act.
