AI 自動權限審查：agent 問你時，誰來回答

AI 自動權限審查替你回答 agent 的權限提示：黑名單先擋下危險指令，白名單放行你已經信任的指令，兩邊都沒命中的才交給 AI 判斷。判斷為允許時，顧問模式給你建議，自動回覆模式幫你按下那個鍵。

agent 跑到一半停下來問「要不要執行這個指令？」，而你剛好不在螢幕前，整個任務就卡在那裡，等這一個按鍵。

AI 自動權限審查就是為這一刻做的。它回答 agent 的提示，一次只按一個鍵，不會替你打指令，也不會去碰畫面上以外的東西。

agent 停下來等你，審查才開始

Agentmux 本來就會辨識 Claude Code、Codex 這類 agent 的狀態。畫面出現「要不要允許」或「選 1 還是 2」這種提示時，它就把那個工作階段標記成等待中，審查從這一刻開始。

同時要符合這幾個條件：

  • 「設定」裡的 AI 自動權限審查開關是開的。
  • 這個工作階段選了「顧問」或「自動回覆」模式，不是「關閉」。
  • 你是 Pro 使用者，或還在試用期內。

同一個提示只會判斷一次，不會每隔幾秒重問一遍。你自己在終端機裡按了鍵或打了字，Agentmux 就取消還在進行的判斷，以你的操作為準。

你切到別的分頁之後，它在背景繼續幫你看著那些不在畫面上的工作階段。

它只讀目前畫面上那一個提示

它先從畫面上找出目前那一個提示：要執行的指令、問題本身，還有可以選的選項。已經捲上去的舊內容不算數。

送給 AI 之前，它會先把畫面裡看起來像密碼、API key、token 的內容遮蔽掉。遮蔽失敗時，原始內容不會送出，這一次也不幫你按任何鍵。

黑名單永遠先跑，而且就在手機上

黑名單在你的手機上比對，永遠第一個檢查。命中就不會送給 AI，直接交給你處理。內建規則涵蓋最危險的幾類操作：

  • 對 /、~ 或家目錄執行 rm -rf
  • sudo
  • git push --force（--force-with-lease 不算）
  • DROP TABLE、DROP DATABASE、TRUNCATE TABLE
  • 把網路下載的內容直接丟給 shell 執行，例如 curl … | sh
  • mkfs、dd if= 這類直接寫入磁碟的指令

這些內建規則可以編輯或移除，你也可以加上自己的規則。

白名單命中，就不用等 AI

有些指令你每天都在按「允許」，例如跑測試或 build。把它們加進白名單，下次命中時，手機自己就決定要按哪個鍵，不用等 AI，也不花 API 用量。

「自動回覆」模式下，你還可以對單一工作階段開啟「允許此工作階段中的所有命令」。這樣會跳過 AI 判斷，黑名單照樣有效，工作階段結束就自動關掉。

白名單命中了，但畫面上找不到明確又安全的鍵時，一樣交給你。

AI 能決定什麼，不能決定什麼？

黑名單和白名單都沒命中的提示，才會送給 AI。它看到的是遮蔽過的畫面，加上你寫的主要意圖，也就是你這次要 agent 做什麼，例如「修好登入頁的測試」。

你可以選兩種引擎：

  • JEV 決策引擎（透過 OpenRouter 或 TypeSafe）：專為終端機裡的提示設計，回應快。判斷分三級：純讀取的安全操作允許；符合主要意圖的指令允許；其餘不相關、看不懂或風險較高的，全部交給你。看起來可疑或像惡意注入的內容會直接拒絕。
  • OpenAI 相容的 LLM：OpenAI、OpenRouter，或是你自己架在本機的模型都可以。

AI 的結論只有三種：允許、拒絕、不確定。只有「允許」會繼續往下走，而且它必須明確指出要按畫面上的哪一個選項。「永遠允許」「不要再問」這類永久授權，它不會選。

顧問只給建議，自動回覆幫你按

每個工作階段可以分別選模式：

  • 顧問（預設）：只給建議。畫面上方會跳出提示，告訴你它建議按什麼，旁邊有「採納」按鈕，按下去才會送出。
  • 自動回覆：判斷為允許時直接幫你按，並跳出提示告訴你它按了什麼。

不管哪一種模式，送出按鍵之前都會再看一下畫面：提示換了、選項順序變了，或是游標不在目標上，就不送。判斷要花幾秒，這幾秒之內畫面可能已經變了，多這一次確認，就是為了不要按到錯的選項。

自動回覆送出一個鍵之後，同一個工作階段會先停 3 秒，才會再送下一個。

哪些情況一定交回給你？

  • 命中黑名單。
  • AI 判斷為拒絕或不確定。
  • 看不出這個提示該按哪個鍵。
  • 要選的是「永遠允許」這類永久授權。
  • 送出前發現畫面已經變了。
  • 敏感資訊遮蔽失敗。

交給你的時候，Agentmux 會照平常的方式提醒你，就跟沒開審查時一樣。

要怎麼打開它？

開始之前先準備好其中一種：

  • JEV 引擎的 API key，透過 OpenRouter 或 TypeSafe 取得。
  • 你自己的 OpenAI 相容 LLM 端點，例如 OpenAI 的 API，或架在自己電腦上的模型。
  1. 到「設定」→「AI 自動權限審查」把開關開啟。第一次會看到資料分享的說明，按下同意之後，會直接帶你進入「進階設定」。
  2. 在「進階設定」選擇引擎、填入你的 API key，按「測試 AI 端點連線」確認可以用。
  3. 回到設定頁，在「自動權限審查模式」選預設模式（先選「顧問」就行），再寫下你的主要意圖。
  4. 連到伺服器、啟動 agent，新開的分頁就會套用預設模式。要調整單一工作階段的模式或主要意圖，點終端機工具列上的自動權限審查按鈕。在那裡也可以開啟「使用我最近的提示」，讓主要意圖跟著你在這個分頁送出的每一條提示更新。

先用顧問模式跑幾天，看看它的建議合不合你的習慣，再考慮對特定工作階段開啟自動回覆。

哪些資料會離開你的裝置？

離開裝置的只有兩樣：遮蔽過的畫面片段，和你的主要意圖。它們送到你自己設定的 AI 服務，用的是你自己的 API key。開啟「使用我最近的提示」之後，你在那個分頁送出的提示會成為主要意圖，也一起送出。Agentmux 不提供也不經手任何 AI 服務。每次判斷的紀錄只存在你的裝置上，可以在稽核紀錄裡查看或清除。模型的推理內容不會儲存。
