Agentmux 指南首頁 疑難排解

為什麼不是 Termius / Blink

通用 SSH app 假設你要打指令。Agentmux 假設你要接回一個正在跑的 agent。這個假設決定了底下每一個功能。

所以這不是在比介面好不好看，是在比誰把「接回」這件事想得更透徹。以下五個功能全部對照現行程式碼查證過，不是隨口列的清單。

tmux-first 自動重連

連上伺服器，Agentmux 直接把上面現有的 tmux session 列出來，點一下就接回去。不用記 tmux ls、tmux attach -t。斷線之後重連，接的還是同一個 session，畫面接著上次的樣子，不必手動重打 attach。

背景維持 + Live Activity

agent 常常一跑就是幾十分鐘。這段等待期就是為它設計的：動態島和鎖定畫面顯示目前進度，跑完可以播提示音。App 不必開在最前面讓你死盯著等結果。

Runestone 編輯器 + Git 工具 + Files app 整合

臨時改一行程式碼，不必在手機上跟 vim 肉搏。內建 Runestone 編輯器直接開檔案改。想看 README 或 agent 產出的說明文件，Ink 提供雙欄 Markdown 預覽，原始碼和排版同時看得到。Git 工具（切換分支、查 diff）和 Files app 整合是 Pro 功能，14 天試用期間也用得到。

Keychain 憑證隔離

私鑰只存在 iOS 系統的 Keychain 裡，不會寫進本機資料庫。開了 iCloud 同步的話，CloudKit 帶走的是伺服器名稱這類非敏感 metadata。私鑰留在原地。

Siri／捷徑自動化

對 Siri 說「從 Agentmux 取得目前終端內容」，GetCurrentSessionContextIntent 就把終端當下的畫面抓進 iOS 捷徑，接去記事本、訊息，或任何你自己組的自動化流程。ContinueLastSessionIntent 更直接：一句「在 Agentmux 繼續工作」接回上一個 session。

這類自動化通用 SSH app 結構上做不到。它們沒有「session／專案／agent」這層語意模型可以暴露給系統。Agentmux 目前實作 6 個 App Intent，涵蓋 Server、Project、TMUXSession、RecentSession 四種 entity。

對繁中使用者，這些修好的地方你會有感

1.3.10 修掉三個英文圈使用者感受不到、繁中讀者一看就懂的痛點。全形字選取時對齊跑掉。連結跨行時複製會斷成好幾截。中日韓詞句裡帶一個斜線就被誤判成檔案路徑。這些坑要實際處理過中日韓文字才踩得到。

什麼時候該用 Termius 而不是 Agentmux

  • 你在極不穩定的行動網路下工作，需要 Mosh 維持連線——Agentmux 目前只有標準 SSH，靠 tmux 自動重連彌補，但那不等於 Mosh。
  • 你需要 Remote／Dynamic（SOCKS5）port forwarding——Agentmux 只有 Local。
  • 你要在 iOS／Android／Windows／macOS／Linux 之間同步大量主機設定，或跟團隊共享主機清單。
  • 你是 SRE／系統管理員，要管幾十上百台伺服器做維運。

Agentmux 為一個工作流最佳化：在手機上接回正在跑的 coding agent。它不是通用維運工具。
