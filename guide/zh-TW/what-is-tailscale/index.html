不要對公網開 port

在家裡的電腦和手上的手機都安裝 Tailscale，兩邊登入同一個帳號，接著 SSH 連線時填那台機器的 MagicDNS 名稱或 100.x 開頭的位址。Tailscale 在你自己的裝置之間建立 WireGuard 加密 mesh，所以不需要對公網開放任何 port，也不需要一個固定的公網位址。

上一篇讓 agent 在你關掉手機之後還能繼續跑，前提是有一條安全的門可以連回去。最直覺的做法是把家裡的 22 port 開到公網，那也最快出事：掃描機器人對全世界的位址全天候敲 22 port，嘗試登入通常不到一天就開始堆積。

第二個問題比較無聊，也更難繞。你家的對外 IP 幾乎一定是動態的，每隔一陣子換號碼；機器又躲在 NAT 後面，跟家裡其他裝置共用那一個對外位址。那裡本來就沒有公網位址可以開。

傳統解法有多痛

在這類工具出現之前，這條路得自己進路由器打通：port forwarding 把公網某個 port 轉給家裡那台機器，DDNS 把主機名稱綁到當下那個 IP，或是向 ISP 買固定 IP，然後自己維護防火牆規則，擋掉除了你以外的每一個人。

每一步都要對。錯一步，要嘛連不進去，要嘛整個家用網路暴露在外。就算全部設定正確，那扇門也永遠開在公網上，你在不在家都一樣。

port forwarding 加動態 IP 為什麼一直出包

四個會動的零件，每一個都在最不方便的時候鬆掉。

  • 位址會變。ISP 重新連線就換號碼，DDNS 客戶端要幾分鐘才跟上。每次變更之後都有一段時間，你存好的名稱哪台機器都不指向；那次更新若在你出門時失敗，名稱從此指向別人的網路。
  • 那個位址常常不是你的。躲在 carrier-grade NAT 背後時，路由器只拿到 ISP 內部網路的一個位址，port forwarding 完全無效——對外那個位址屬於 ISP，好幾個使用者共用。
  • 多一個轉發就多一扇門，通往一個住著智慧電視和舊攝影機的網路。
  • 它必須永遠正確。韌體更新會清掉規則，換路由器要全部重建，機器換了區網位址，轉發就指向空處。

真正的代價是出錯那一刻：你在月台上，用行動網路的手機檢查家裡的路由器，而你要連的東西剛好連不到。

Tailscale 做了什麼

Tailscale 是一個 WireGuard mesh。每台裝置裝好、登入同一個帳號，裝置之間就直接建立一條加密連線。沒有一個對外入口，也沒有一個 port 被開在公網上等人掃描。

每台裝置產生一對 WireGuard 金鑰，私鑰那半從不離開裝置。公鑰互相交換，換完那些就是隧道。帳號那一側是帳務：介紹裝置彼此認識、記下每台現在在哪裡可達、發出公網不會路由到的私有位址。

MagicDNS 給每台裝置一個你記得起來的名稱，解析由它自己處理，你不必碰那個會變的 IP。裝置在 NAT 後面、位址昨晚換過、從家裡的 Wi-Fi 切到行動網路——這些穿透都在背後完成。

手機也在 NAT 後面，mesh 為什麼還行

行動網路讓問題更糟。手機也沒有可以被連進來的公網位址：4G、5G 之下它躲在 carrier-grade NAT 後面，跟大量使用者共用同一個對外位址。依賴「從外面敲門」的做法，兩端同時失效。

mesh 是反過來的設計：兩邊都只需要往外送封包。手機送一顆，機器送一顆，雙方各自知道對方看起來在哪裡，再試著穿過自己的 NAT 開出一條直連。加密由 WireGuard 負責，介紹由 mesh 負責。找不到直連時，流量改走中繼站而不是失敗，仍然是端到端加密。

心智模型：多一個只有你連得到的位址

你家那台機器多了一個私有位址。只有登入同一個 Tailscale 帳號的裝置看得到它、連得到它。掃描機器人不知道它存在，因為它從沒出現在公網上，而你的路由器什麼都沒改。

從這裡開始，你的 SSH 連線打的就是這個位址，不是那個天天被人敲門的 22 port。

你該打的到底是哪個位址？

不是區網那個。一台機器在這個架構下同時有三個位址，只有兩個值得存進 app。

位址在哪裡連得到要不要用
區網位址，例如 192.168.1.23 只有那個 Wi-Fi 底下 不要。手機切到行動網路就沒有路走到它
ISP 給路由器的位址 carrier-grade NAT 之下哪裡都不通 不要。它會變，而且是路由器的
MagicDNS 名稱，例如 mac-mini.tail1234.ts.net 任何網路，兩端隧道都開著就行 要。存這個
100.x.y.z 跟名稱一樣 留一組，名稱解析壞掉時用

區網位址說明的是那個區域網路，不是你的機器。存名稱，機器換 Wi-Fi、換 IP、甚至搬家都還連得到。機器上打 tailscale status，兩個值都會列出來。

兩台裝置看起來都連線了、SSH 還是失敗，先查你填的那個位址。Tailscale 顯示已連線，SSH 仍連不到那一節有完整的順序，包括機器被登出、需要重新登入的情況。

這樣做你要付出什麼

三筆成本，在擠進捷運之前先知道，比事後知道好。

機器上多一個常跑的程式。它隨開機啟動、偶爾自己更新、也有自己的 bug。機器連不到的時候，要多排除一個嫌疑犯，才輪到 SSH。

有一個你在錯誤時刻需要它的控制面。流量是裝置對裝置，介紹不是。新的筆電、剛換掉的手機、過期的憑證——在它們重新登入之前都不在你的網路裡。這個登入若在你出門時失敗，機器好好的，你就是連不到。留一條不依賴那台裝置的入路。

手機必須維持連線。手機上那條隧道是一個 VPN profile，手機會把它關掉：重開機之後、別的 VPN 接手之後、你點掉那個要求的時候。除錯之前先確認它還開著。它只承載連往你自己那些位址的流量。

私人網路不是改回密碼的理由

看起來合理的推論是：一台公網連不到的機器，門上不必上鎖。它需要，而且有兩個理由。

mesh 的安全現在就是帳號的安全，任何能登入的裝置都在裡面——一台你已經信任的裝置。忘在計程車上的筆電不是掉在公開 Wi-Fi 上，它在你自己蓋的網路裡面，每台機器都可達，也沒有別的東西攔它。金鑰讓那台裝置還是要證明自己是誰，才走得到下一步。

再來是縱深。mesh 讓外面的人進不來，金鑰讓已經在裡面的陌生人走不下去。兩件獨立的事情都失效，才會有人開始動你的專案。密碼只是一個可以被猜的東西，而猜的難度剛剛又變低了。金鑰怎麼完成證明在 SSH 那一篇。

什麼時候根本不需要 Tailscale

如果機器和手機永遠在同一個 Wi-Fi 底下，跳過這一步。區網位址能用，不用裝東西，不用登入帳號——條件是你一走出家門就全部失效，而這篇處理的正是出門之後。

自己租的伺服器是另一種算法。位址不會動，沒有路由器要設定，玩壞了也不會把自己鎖在外面。風險換成 22 port 永久面對公網。有人還是會在上面跑 mesh，把 SSH 收到私有位址後面；有人維持公開，完全依賴金鑰。兩種都可行，不可行的是暴露在公網的 port 用密碼。

如果你已經透過別人管理的網路碰到那台機器——公司的 VPN——就走那條路。兩條重疊的隧道不會讓你更連得到，只會讓除錯更難。不確定自己屬於哪一種？設定頁問三個問題，然後回給你一張排好的清單。

進來的路解決了。剩下的是你手上那台裝置，以及它假設你為什麼來了。
