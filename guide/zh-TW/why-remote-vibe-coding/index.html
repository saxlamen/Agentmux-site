你的 AI 應該在你睡覺時工作

CLI agent 真正的成本是待命，不是打字：你講三十秒，接下來幾個小時不能離開位子。把它跑在你從來沒關過的機器上，用 tmux 讓 session 斷線照跑，再用 SSH 加 Tailscale 從手機接回去，待命就變成一部手機加十五秒，而它在你睡覺的時候繼續工作。

如果你已經在用 Claude Code 或 Codex，大概感覺過這件事：做事的是它，被綁住的是你。會被綁住不是因為你不肯放手，是因為那個 agent 只住在你這台機器上的一個視窗裡。

時間花到哪裡去了？

一輪 CLI agent 的工作，節奏幾乎都是同一個樣子：

你講 30 秒 → 它跑 5–20 分鐘 → 它需要你決定一件事 → 重複

把一整天的比例攤開來看，吃掉時間的不是打字。你描述需求那 30 秒，是全程最短的一截。剩下全是等：等它讀完專案，等它改完十幾個檔案，等測試跑完。然後它停下來問：「這個 migration 要不要順便處理？」你回一句話，接著又等五分鐘、二十分鐘。

一天下來，你真正打字的時間可能不到十分鐘，被佔掉的是好幾個小時。這幾個小時你在待命：什麼都沒做，但不能走開，因為它隨時可能要你回一句話。

傳統做法把待命綁死在一台筆電上

這種待命有一個實體位置。agent 跑在你筆電的終端機視窗裡，視窗連著那個 shell，shell 連著那台不能關掉的機器。於是你只有兩個選擇：

坐著等。人留在椅子上，盯著那個大部分時間什麼都不發生的畫面，只為了在它問的時候三十秒內回話。一小時換三句回覆。

或者關掉筆電。合上蓋子，process 被停掉或直接死掉，session 沒了，agent 累積下來的脈絡也一起消失：它讀過哪些檔案、改到哪一步、為什麼選這個做法。晚點回來只能重開一個，整段重講一次，從頭跑。

兩個選擇付的是同一筆代價。真正綁住你的是那台機器在哪裡，不是工作本身。

哪三個零件解開這個綁定？

這個綁定不是一整塊，是三層疊起來的。每一層都有現成的標準工具可以拆，而那些工具都已經存在幾十年了。單獨看，三樣都很普通；疊起來才是重點：

零件解開的綁定
CLI agent 是純文字 process，不需要圖形介面 → 可以住在別台機器上
tmux session 釘在伺服器上，斷線照跑 → 待命不需要你在場
SSH + Tailscale 從任何網路安全接回，不開公網 port、不需固定 IP → 待命不綁定裝置與位置

順序不能換。先有 CLI，agent 才可能離開你的筆電，搬到家裡那台從來沒關過的 Mac mini 上。接著是 tmux，session 釘在那台機器上，你的連線斷掉它照樣跑。最後是 SSH 加 Tailscale，你才能從捷運上、從公司、從別人家的 Wi-Fi 接回同一個 session，而且不用在路由器上開任何一個對外的 port。

少任何一個都不成立。只有 CLI 沒有 tmux：一斷線，agent 就死。有 tmux，沒有安全的進入方式：你只能在家裡用它。

待命的成本是一部手機加十五秒

三層都拆掉之後，待命的代價從一台筆電加一個固定位置，降到一部手機加十五秒。要確認它跑到哪裡，你不用再找桌子、位子和電源。

只要十五秒，你就不用再排一段時間來顧它。排隊看一眼，等紅燈看一眼，睡前看一眼，回一句「用第二個方案」，手機收回口袋，agent 繼續往前跑。

待命一旦不需要你在場，工作就能排進你本來就不在場的時間。丟一個重構任務給它，去吃晚餐。睡前開一個修測試的 session，早上起床看結果。那台機器每一個晚上本來都閒著。

還有其他做法能接到自己的 agent 嗎？

要從遠端接到自己的 agent，路不只一條。把這些做法放在同一組標準下比，差別就很清楚，尤其是最後一欄。多數人是事後才發現自己卡在那一欄。

做法 待命成本 脈絡存活 需要的網路設定 能不能真的改檔案
帶著筆電 要帶一個包、找位子、找電源 合上蓋子就停 不用，但機器得跟著你走 能，改的是本機的檔案
VNC 遠端桌面 需要一塊夠大的螢幕，還要用手指操作滑鼠 UI 桌面 session 留著就活著 要打通 VNC 或另外架 VPN 能
網頁版 agent 低，開瀏覽器就好 活在對方的伺服器上 不用 改的是雲端沙箱裡的副本，不是你機器上那份
Codespaces 這類雲端環境 低，但要能開瀏覽器 閒置久了容器會被回收 不用，但要把專案放上雲端，並依用量計費 能，但改的是雲端容器裡的那份 repo
通用 SSH App 手機就行 靠 tmux，撐得住 要自己處理安全連外 能，但介面是把桌面終端機直接搬過來
Agentmux 手機，十五秒接回 tmux 在伺服器上，跟手機在不在無關 Tailscale，不開公網 port 能，改的就是你自己機器上那一份

跑在別人雲端沙箱裡的 agent，改的永遠是一份副本：你的 .env 不在那裡，今天早上裝的那個內部套件不在，那個只有本機跑得起來的資料庫也不在。

走 SSH 加 tmux 這條路，agent 就坐在你自己的機器上，用你的環境，改你的檔案。唯一的差別是這一次換你的手機看著它。
