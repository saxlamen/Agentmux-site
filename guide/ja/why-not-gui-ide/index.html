CursorやVS CodeではなくCLIを選ぶ理由

Cursor や VS Code の中にあるエージェントは GUI プロセスの一部として動くため、画面とログイン済みのデスクトップ、そしてその前に座る人間を必要とします。一方、CLI エージェントのインターフェースは文字列のストリームであり、tmux によって丸ごと保存してどの端末からでも再接続できます。これはアーキテクチャの違いによるものです。

すでに Cursor や、エージェント拡張を入れた VS Code を使っていて十分に機能しているなら、同じ作業のために SSH と tmux を学ぶ意味があるのは 1 つの場面だけです。それは、あなたがそのマシンの前に座っていないときです。

アーキテクチャの違い

GUI IDE の中にあるエージェントは、その GUI プログラムの一部です。アプリケーションのプロセス内で動き、状態はそのウィンドウのメモリ上に置かれ、出力はキャンバスに描画されます。

だからこそ画面とログイン済みのデスクトップセッション、そして前に座る人が必要になります。ウィンドウを閉じればエージェントも一緒に終わるのは、そのプロセスの一部として動いているためです。

CLI エージェントのインターフェースはバイトストリームです。文字が入り、文字が出ていくだけで、途中にグラフィカルな要素はありません。このようなストリームはアタッチ（接続）、デタッチ（切り離し）、再アタッチ（再接続）ができます。

80×24 の文字マトリクスは丸ごと記憶してどんな画面にも描き直せるため、tmux がその管理を引き受けます。ノート PC でも、スマホでも、友人の iPad でも構いません。やり取りされているのは文字だけなので、端末を切り替えても何も失われません。

CLI エージェントがリモートで機能する理由はすべてここにあります。ピクセルのキャンバスはシリアライズして再接続できませんが、文字のマトリクスはできるからです。これは技術的な制約によるものです。

作業の途中でノート PC を閉じると何が起きるか

終業間際にエージェントへ大きなリファクタリングを頼んだとします。少なくとも 20 分はかかり、あなたはもう席を立ちます。

Cursor を開いたままにする tmux + Claude Code
ノート PC を閉じる エージェントが止まる エージェントは動き続ける
2 時間後 開くとコンテキストが消えており、最初からやり直し スマホを開くと完了している

右側の列にあるものは、エージェントの賢さとは無関係です。そのセッションは最初からノート PC 上にあったわけではありません。電源を切らないマシン上にあり、ノート PC はしばらくそこに接続していただけです。蓋を閉じたことで接続が終わり、作業はあなたなしで続きました。

現在の Cursor にはクラウドのバックグラウンドエージェントもあり、ノート PC を閉じても動き続けます。ただし動いているのは Cursor 側のリモートサンドボックス内のコピーであって、手元のマシンのエージェントではありません。この点は他のページで触れているブラウザ型エージェントや Codespaces と同じです。自分のマシン上のエージェントに何が起きるかを表すのは、やはり左側の列です。

「リモートデスクトップを使えばいいのでは？」

いちばんよく出る反論であり、理屈の上では筋が通っています。向こうのマシンではデスクトップが動いたままなのだから、VNC で繋ぎ直せば Cursor も開いたままで解決する、と見えます。

しかし実際には、両者が送っているものが違います。VNC はピクセルを送り、SSH は文字を送ります。画面全体の更新 1 回が画像データなら数百キロバイトから数メガバイトになるところ、同じ画面を文字として送れば数キロバイトのテキストで済みます。およそ 3 桁の差です。

この差は日常のあちこちで効いてきます。電車の中、エレベーターの中、アンテナが 1 本しかない場所では、VNC は紙芝居になり、1 回のスクロールを描き直すのに 3 秒かかります。同じ回線でも SSH の文字は即座に届きます。

帯域に余裕があっても、今度はマウスと 1440p ディスプレイ向けに作られたデスクトップ UI を 6 インチのタッチ画面に押し込む問題が残ります。メニュー項目を 1 つ押すために拡大し、狙いを定め、タップすることになります。タッチ操作を前提に作られていない画面は、回線が速くなっても使いやすくはなりません。

机の前では IDE のほうが優れていることも多い

机の前では IDE のほうが優れている場面が多いです。定義ジャンプ、リファクタリング機能、デバッガなどは、どれもスマホ回線越しには使えません。IDE は「自分がそこにいて操縦するとき」に向き、CLI エージェント＋リモート接続は「走らせておいて様子を見に来るとき」に向きます。

併用できるなら両方使うのがいちばんです。机にいる間は Mac の IDE を使い、席を離れたら Agentmux で同じプロジェクトの同じエージェントに再合流します。

Agentmux が置き換えるのは IDE ではなく、椅子に座って待っている時間です。そしてスマホをポケットに入れ、トンネルの中で電波が切れたとき、そのセッションに何が起きるかという次の問題が出てきます。
