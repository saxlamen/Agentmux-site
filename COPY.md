### The word for the multiplexer

Before this change the app's install flow said "tmux" on every host, in all ten
locales, while the only text that named psmux was three English-only Swift
literals. Since then the rule is: **the program is named after the host, the
protocol is named tmux everywhere.** A Windows host gets psmux in the button,
the badge, the step rows and the failure messages, because that is what winget,
`where.exe` and `psmux --version` all answer with. Sessions, keys and commands
stay tmux on both hosts: "kill tmux session", `Ctrl-b`, "Switch tmux windows",
and the whole vocabulary this guide teaches.

- The decision lives in one place: `MultiplexerNaming.name(distro:serverOS:)` in
  `Agentmux/Services/TmuxInstaller.swift`. 17 keys take the name as `%@`, and
  the three installer messages are now localized strings instead of literals.
- Consequence for this site: wherever the guide quotes one of those sentences it
  must quote the app's value **for that locale**, not a hand translation of the
  English. The zh-TW pages quote the zh-Hant string.
- `MultiplexerNamingTest` in `test_copy_i18n.py` is the ratchet: all 20 keys
  present in all 10 app locales, exactly one `%@` each, no literal program name
  left in the 17, psmux named in both Windows messages, and the quoted sentence
  still findable in the guide's en and zh-TW pages. Program names are matched as
  words, because "Agentmux" is spelled with tmux at the end.

The size column in the table below comes from `tools/copy_stats.py`. Run it
instead of trusting a number written here: it counts reader-visible text (tags,
script and style removed), in words for English and in CJK characters for
Chinese and Japanese, which are not comparable units.

**There is no CI gate here, on purpose.** The site repo has no
`.github/workflows/`: GitHub Pages deploys the branch with its own build and
deploy jobs, and neither one knows these test files exist. Running the five
files locally before pushing is the agreed gate: it is the only check between an
edit and a live page.

Run the builder that owns the file you edited, then the tests. Home edits never
touch `guide/`, and guide edits never touch the homepages.

**The home page's message lives in four places.** The hero slots in
`index.source.html`; `LANG_CONFIG` in `build_home.py`, which paints the
`<title>`, description and og tags a crawler sees; `LANG_META` in a `<script>`
of `index.source.html`, which repaints those same tags when a visitor switches
language in the browser; and `FEATURE_LIST` / `OFFER_DESCRIPTION`, the JSON-LD.
Change a claim in one and check the other three. `test_copy_i18n.py` fails if
the two metadata copies disagree, if either is too long for a search result, or
if a locale is missing from either.

Keep terms inside a locale consistent, and keep the cross-locale mapping above.
Technical words stay untranslated in the Chinese locales (SSH, tmux, agent,
session, commit, port); Japanese writes them in katakana (セッション, コマンド)
or keeps the Latin form (SSH, tmux). Never translate an English idiom
literally.

`test_copy_i18n.py` enforces the orthography: no mainland terms or simplified
characters in a zh-TW surface, no traditional characters or Traditional house
terms in a zh-Hans surface, no Chinese left sitting in a ja surface.

Apple and Google product names stay Latin in all four locales: Keychain, iCloud
Keychain, Keystore, Live Activities, Google Drive, and `build number` (no
established Chinese legal term; Apple's own 建立編號 is App Store Connect
jargon). Japanese uses です/ます throughout, including the privacy policy, even
though Japanese legal text often uses である体: the site reads as one voice this
way, and half a page in である体 would read as a different author. If a Japanese
reviewer ever asks for である体, convert the whole locale at once.

## Voice

The home page sells a capability, not a feeling. Concrete nouns and the real
mechanism beat adjectives, the same rule the guide follows. Banned on the home
page, same list as the guide: seamless, powerful, robust, effortless, intuitive,
game-changer, supercharge, streamline, exclamation marks, emoji, "in today's
fast-moving world", "whether you're a beginner or a pro", rhetorical "Let's".

Privacy copy is a different animal: it states what the app does with data and
stops there. No voice, no metaphor, no reassurance kicker; if a sentence needs
hedging, the product behaviour is unclear, and the copy is not where to fix it.

Em-dashes are allowed by house style, and every surface uses them sparingly
(the guide went from 124 site-wide to 1 in the last copy pass). Zero is fine,
one or two per article is fine, a paragraph that leans on one every sentence is
not.

## What `test_copy_i18n.py` guards

- Every locale has real copy on home and privacy, at least 200 visible
  characters, and no locale runs more than 4× shorter than the longest one,
  which is how a dropped section shows up.
- The zh and ja blocks are mostly written in their own script, so a slot that
  was never translated fails instead of shipping English.
- Orthography and terminology per locale (see above).
- Each generated homepage paints its own language before JavaScript runs, and
  every homepage carries all four `hreflang` values plus `x-default`.
- The two copies of the home page's title and description agree with each other,
  cover all four locales, and fit a search result (en 60 / 160, CJK 60 / 100).
- Every homepage's guide link points at a guide locale that is actually built,
  through `GUIDE_FALLBACK = {"zh-Hans": "zh-TW", "ja": "en"}`.
- `KNOWN_GUIDE_GAP = {"zh-Hans", "ja"}`: the home nav offers 指南 and ガイド to
  readers whose guide does not exist yet. This is a ratchet. When the guide
  gains a language, delete it from that set and from `GUIDE_FALLBACK` in the
  same commit that adds it to `guide-src/config.json`; if the set no longer
  matches, the test says so.

## The announcement payload

`announce.json` is one in-app release popup. `../docs/archive/announce.schema.json`
and `../docs/TELEMETRY.md` describe the wire format and are the reference; this
section records the parts that are copy or judgement.

- **One payload, one slot.** Publishing a new object replaces the previous one
  for everybody. A feature note about 1.4.5 is gone the moment 1.5.0's appears.
- **The line budgets the iOS popup can render:** title 34 characters, message
  140 on iPhone (an iPad allows 180), button label 26. They come from the
  popup's SwiftUI layout rather than the schema, and longer text is cut. The
  1.5.0 message is 149 characters in English: it fits iPad and is cut on iPhone.
  The app's text layout has not been re-measured since the popup shipped, so
  work to 140 and put the point in the first half of the sentence.
- **`minAppVersion` is advisory in the schema and applied by the app**, so
  nothing stops a payload about a feature an older build lacks. A feature that
  arrived in one release must set `minAppVersion` and the same value per
  platform under `platforms`, or readers on an older build tap a button for a
  screen they do not have. The live payload (`2026-11-10-windows-and-attach`
  since 2026-11-10, expiring 2026-12-20) gates itself to 1.5.0 that way, and its
  CTA is `guide/en/windows-server/`.
- **`scripts/check_announce.py`** validates the rules that are easy to get wrong
  by hand: schema keys and types, `expiresAt` later than `publishAt`, real
  semver in the version gates, both `platforms` keys, the ten locale keys the
  apps ask for, `zh-Hans` and `zh-Hant` written in their own script, and an
  `https` CTA whose path exists on this site (a HEAD request, so run it after
  the page is deployed). It checks none of the copy: no length budgets, no
  terminology, no simplified characters in `zh-Hant`, no banned marketing words.
  It uses only the standard library, so it runs anywhere Python does.
- The popup is a **release note you cannot reread**: dismissed once, never
  offered again on that device, and `expiresAt` is not a dismissal. Say one
  thing, put the detail behind the button, and expect a reader to tap it or
  ignore it rather than read it twice.

## Known gaps

1. `404.html` is English-only while everything else speaks four.
2. The guide exists in en and zh-TW. The home nav in `zh-Hans` and `ja` labels it
   指南 and ガイド, and `build_home.py` rewrites that link to a guide locale that
   exists: `zh-Hans` readers get the Traditional Chinese guide, Japanese
   readers get the English one. `GUIDE_FALLBACK` in `test_copy_i18n.py` pins
   that behaviour so it changes on purpose rather than by accident.
3. `zh-Hans` and `ja` have no terminology sheet of their own; the mapping table
   above is the only reference, and it is short.
4. `privacy.html` names two app switches in four languages each: the statistics
   switch (Share Anonymous Usage Statistics / 分享匿名使用統計 / 分享匿名使用统计 /
   匿名の利用統計を共有) and the background-alert master (Background Activity
   Alerts / 背景任務警報 / 背景任务提醒 / バックグラウンド活動アラート). It used to
   name a "Background Activity Chime", which the app has never shown. The names
   live one repo over, in `Agentmux/Resources/*.lproj/Localizable.strings`, so
   `test_copy_i18n.py`'s `AppLabelTest` now checks them in both directions: a
   rename on the settings screen and a policy that stops naming the real label
   each fail their own test. The test skips itself when the app is not checked
   out beside the site.
5. An article's `title` in `guide-src/strings/*.json` is also its on-page `<h1>`,
   its `og:title` and its JSON-LD headline. There is no way to shorten a search
   result title without changing the heading a reader sees, which is why
   `test_build.py` caps it. Five headings changed in the last strings pass.
6. The setup wizard builds a plan for every answer, Windows included. It used to
   answer "A Windows PC" with the setup article's `#windows` section and no
   checklist, because there was nothing on Windows to install; Agentmux 1.5.0
   drives psmux there, so Windows now has five steps of its own. Two tests hold
   the new state: `test_no_machine_answer_is_routed_to_prose` (no machine answer
   may go back to being prose) and `test_no_windows_step_hands_the_reader_a_posix_command`
   (the old bug: a Windows reader handed `which claude`). The `explain`
   mechanism in `guide-src/wizard.js` still exists and is now unused.
7. `wizard/strings/*.json`'s `ui.loadFailed` text is duplicated verbatim inside
   `guide-src/content/setup/{en,zh-TW}.html` (`data-load-failed`). Change one and
   the guide's fallback message stops matching the wizard's.
