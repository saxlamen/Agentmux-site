# Website copy: where it lives and what guards it

Read this before changing any text on the site. The guide's own rules are in
`guide-src/WRITING.md`; this file covers the rest of the site and the fact that
the site speaks **four languages** while the guide speaks two.

## Commands

```
python3 build_home.py                      # home, four locales
python3 guide-src/build.py                 # guide, two locales, llms.txt, sitemap
python3 guide-src/site_map.py              # SITE_MAP.md and SITE_MAP.svg
python3 guide-src/tests/test_language.py   # zh-Hant guide copy
python3 guide-src/tests/test_build.py      # guide builder, 82 tests
python3 guide-src/tests/test_site_map.py   # the map stays honest
python3 guide-src/tests/test_wizard_data.py
python3 guide-src/tests/test_copy_i18n.py  # the four-locale surfaces
```

Run the builder that owns the file you edited, then the tests. Home edits never
touch `guide/`, and guide edits never touch the homepages.

**The home page's message lives in four places.** The hero slots in
`index.source.html`; `LANG_CONFIG` in `build_home.py`, which paints the
`<title>`, description and og tags a crawler sees; `LANG_META` in a `<script>`
of `index.source.html`, which repaints those same tags when a visitor switches
language in the browser; and `FEATURE_LIST` / `OFFER_DESCRIPTION`, the JSON-LD.
Change a claim in one and check the other three. `test_copy_i18n.py` fails if
the two metadata copies disagree, if either is too long for a search result, or
if a locale is missing from either.

## The four locales are separate drafts

`zh-Hans` and `ja` are not machine translations of `en`, and `zh-TW` is not a
translation either — the same argument gets written in each language. The
current copy is in step, measured across home and privacy:

| Concept | en | zh-TW | zh-Hans | ja |
|---|---|---|---|---|
| server | server | 伺服器 | 服务器 | サーバー |
| terminal | terminal | 終端機 | 终端 | ターミナル |
| session | session | session | 会话 | セッション |
| device | device | 裝置 | 设备 | デバイス |
| plans | plans | 方案 | 方案 | プラン |
| guide | guide | 指南 | 指南 | ガイド |
| privacy | privacy | 隱私 | 隐私 | プライバシー |

Keep terms inside a locale consistent, and keep the cross-locale mapping above.
Technical words stay untranslated in the Chinese locales (SSH, tmux, agent,
session, commit, port); Japanese writes them in katakana (セッション, コマンド)
or keeps the Latin form (SSH, tmux). Never translate an English idiom
literally.

`test_copy_i18n.py` enforces the orthography: no mainland terms or simplified
characters in a zh-TW surface, no traditional characters or Traditional house
terms in a zh-Hans surface, no Chinese left sitting in a ja surface.

## Voice

The home page sells a capability, not a feeling. Concrete nouns and the real
mechanism beat adjectives, the same rule the guide follows. Banned on the home
page, same list as the guide: seamless, powerful, robust, effortless, intuitive,
game-changer, supercharge, streamline, exclamation marks, emoji, "in today's
fast-moving world", "whether you're a beginner or a pro", rhetorical "Let's".

Privacy copy is a different animal: it states what the app does with data and
stops there. No voice, no metaphor, no reassurance kicker; if a sentence needs
hedging, the product behaviour is unclear, and the copy is not where to fix it.

Em-dashes are allowed by house style, and every surface uses them sparingly
(the guide went from 124 site-wide to 1 in the last copy pass). Zero is fine,
one or two per article is fine, a paragraph that leans on one every sentence is
not.

## What `test_copy_i18n.py` guards

- Every locale has real copy on home and privacy, at least 200 visible
  characters, and no locale runs more than 4× shorter than the longest one,
  which is how a dropped section shows up.
- The zh and ja blocks are mostly written in their own script, so a slot that
  was never translated fails instead of shipping English.
- Orthography and terminology per locale (see above).
- Each generated homepage paints its own language before JavaScript runs, and
  every homepage carries all four `hreflang` values plus `x-default`.
- The two copies of the home page's title and description agree with each other,
  cover all four locales, and fit a search result (en 60 / 160, CJK 60 / 100).
- Every homepage's guide link points at a guide locale that is actually built,
  through `GUIDE_FALLBACK = {"zh-Hans": "zh-TW", "ja": "en"}`.
- `KNOWN_GUIDE_GAP = {"zh-Hans", "ja"}`: the home nav offers 指南 and ガイド to
  readers whose guide does not exist yet. This is a ratchet. When the guide
  gains a language, delete it from that set and from `GUIDE_FALLBACK` in the
  same commit that adds it to `guide-src/config.json`; if the set no longer
  matches, the test says so.

## Known gaps

1. `404.html` is English-only while everything else speaks four.
2. The guide exists in en and zh-TW. The home nav in `zh-Hans` and `ja` labels it
   指南 and ガイド, and `build_home.py` rewrites that link to a guide locale that
   exists: `zh-Hans` readers get the Traditional Chinese guide, Japanese
   readers get the English one. `GUIDE_FALLBACK` in `test_copy_i18n.py` pins
   that behaviour so it changes on purpose rather than by accident.
3. `zh-Hans` and `ja` have no terminology sheet of their own; the mapping table
   above is the only reference, and it is short.
